# #205 单位 PK 升级前后对比

实现规格，2026-10-19。依据 issue #205；本文件记录实现选择，不代表 Steve 或 Kent 审批。

## 范围与操作

只在双方均可用的 1v1 中启用。保存时将当前 A 科技作为升级前，B 全部配置固定；保留双方单位形态、文明、时代、团队加成。继续使用上方 A 的科技详情选择当前方案。支持取消基准已有科技，但明确列出取消项、不退款；这是方案比较，不代表游戏能撤销研究。

保存、重新保存、清除按钮均至少 44×44。保存后显示两列「升级前」「当前方案」及第三列「变化」，完整科技清单位于各方案卡片。可复制完整比较链接；每列另有独立 1v1 链接用于核对。

## 数据与状态

- 加载：复用 PK 加载态，不提前计算。
- 无基准：解释固定 B、仅改 A 科技，提供保存按钮。
- 已保存但未改变：两列一致，变化为 0，提示尚无科技变化。
- 已改变：同时展示 A 生命/攻击/两类护甲/攻击间隔/命中率/射程/移速；双向每击、期望伤害、击杀次数、用时、DPS；胜负、战斗时长和剩余生命。零差值显示「不变」，击杀次数允许不变。
- 新增/取消：列完整科技名称及链接；新增必要前置单独标记；费用仅算当前前置闭包减基准闭包，取消不退款。研究费用和单位训练费用分开，研究时长是合计，不模拟并行研究或研究期间军力。
- 无法选择：非 1v1 或任一方不可用时说明原因，保存按钮禁用。
- 无效：单位、文明、时代、团队、B 任意配置、模式或数据版本变化即失效，不计算差值。保留醒目的状态说明，允许清除/重新保存。非法、未来时代、无效果或不支持 ID 的分享参数也失效，不能静默丢弃后比较。
- 前置：双方各方案使用同一文明和时代下可用前置闭包。分享参数只存显式完整科技 ID、完整团队 ID，不保存 f/c 预设。循环、缺失或不可用前置拒绝比较。

URL 继续使用 a/b/m，新增 base（升级前 A）、fixed（固定 B）、basev（数据版本）。保存时 a/b 同步写成展开后的完整配置。失效的上下文仍保留在 URL，以便刷新后显示原因，不自动恢复比较；清除会删除三个参数。

## 模型与费用口径

复用 simulator 与 duel。移速、射程、弹道、地形、操作、特殊能力等实战价值未被 1v1 模型模拟；即使差值为零，也不能据此判断科技无用。文本科技仅说明，不参与可选计划。两列均显示当前固定数据版本与上述限制。

科研使用 techs.json 基础价；文明科研折扣、免费科技、返金及研究速度加成未计入，明确展示该原因。训练费用独立展示，不从科研投入中扣减。

## 四档宽度、主题与令牌

1280：两张方案卡片并列，各自完整科技、训练费、数据版本；下方三列表格（指标/升级前/当前方案），变化放在当前数值下。360/375/390：两卡纵排，三列表格保持视口宽度，指标可换行，数值与单位不拆行；长科技名称正常换行，不让整页横向滚动。费用使用可换行的资源组，每个数值与资源标签不拆开。表头一直显示前后标签。

背景 --color-surface，次级卡片 --color-surface-2，边框 --color-border，分隔线 --color-line；正文 --color-text，说明 --color-muted，链接 --color-link，差值 --color-accent，无效 --color-warn。差值不用颜色独自表达含义。字号正文 14px、说明/差值 12px、标题 18px；间距 8/12/16/24px，圆角 12px。浅深主题均使用同组语义令牌，无硬编码色。

## 验证

固定数据测试：Byzantines 城堡时代骑士 u38 对骑士，空科技增加锻造 67，击杀次数 13 至 12；骑士 [67] 增加铸铁 68 对长枪兵 u358，攻击提高但击杀次数保持 5；增加畜牧 39 只改移速而战斗结果不变。逐列等于独立 PK。另测前置差集/重复/取消、无效 URL、全部失效路径、分享刷新、四宽浅深截图及无溢出/无页面错误。
