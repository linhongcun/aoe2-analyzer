# #25 PK 盈亏平衡点 · v3 交互规格（Jony）

口径不变：B 默认 10、可改；A 搜索上限 200；平局不算获胜，必须严格获胜；集火模型与群战一致。

## 结论
- 「{N} 个{A}，才能打赢 {M} 个{B}」，N 为大号琥珀数字（64 / 移动 48），全视图唯一琥珀数字。
- 1v1 入口：B 固定 1 个，「{N} 个{A}，才能打赢 1 个{B}」。
- 三档表 N−1 / N / N+1；结果用图标+文字：check「A 胜」/ x「A 负（含平局）」。N = 1 时不显示 N−1。
- 「怎么算的」说明里写明「平局算没打赢」。

## 上限
- 200 内无法取胜：红底提示「200 内无法取胜」+ 200 个时的战损（沿用 v2 画法，未改）。

## 旧结果变灰
- 任一参数改动后：顶部条「参数已变，请重新计算」+「重新计算」按钮；结果卡整体 45% 不透明度 + 灰度，不自动重算。1v1 入口同样适用。

## 价格口径（内部）
- 盈亏平衡**目前按精确浮点价计算**（N 只看数量，不受取整影响；若后续扩展到按资源算，也用精确价）。是否改用取整后的价格，等 hongcun 游戏内实测后再定。UI 不显示任何「待核」字样。
