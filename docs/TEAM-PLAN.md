# 团战分工计划

`#/team-plan`记录单方2–4名玩家在封建、城堡、帝王三个阶段的出兵与支援约定。位置由玩家自记，人数与文明评分不会强制位置；2v2可以不设口袋，也可记录特殊地图的口袋位。可同时选同一文明。

范围按[冻结规格](design/v0.25.0-community-completion.md)及[前置工程审阅](design/v0.25.0-readiness-review.md)。本模块不新增共享前置模拟器，不更改既有生产、团队加成或战斗模型。

## 兵种与前置

固定DE185872，支持39个常规陆战具体形态，清单在`src/content/team-plan.json`。其它目录内具名单位可记录，显示“暂未支持”，不代换为近似兵种。未知实体ID原样保留并报错，可重新选择或取消相应确认。

每玩家每阶段独立记录主副形态、生产地点、`completedForms`、`completedUnlockTechIds`、`completedBuildings`以及资源兵力自报。`completedForms`表示用户明确确认此精确形态所需升级已经实际完成，包含其所需前置升级；系统不独立执行完整研究链。免费升级也由本人确认。高形态已确认又选择同线低形态时，显示已被升级取代并保留记录。

领域wrapper复用production的文明、树格、有效时代与潜在地点判定，包括亚美尼亚、勃艮第、波希米亚与库曼的既有例外。查询潜在地点时可以反事实提供生产科技；查询结果与自动补齐、免费集合绝不回写用户确认。火枪手5、手推炮36的化学47独立确认。形态升级候选索引仅辨识升级形态，多候选不作AND要求；基础形态白名单与索引在专项测试逐项核对。不从`Unit.b`单值推断地点。

输出区分引用无效、暂未支持、该文明不可用、时代未到、已被升级取代、尚缺前置、所列前置已满足。最后一种只对应已列的数据条件与用户确认，始终另列资源兵力自报，不表示资源、人口、兵力或实际支援足够。

## 任务与协作

侦察、破城、掩护、支援仅在用户选择需要后检查。负责人主动认领，允许多人负责两侧；无负责人显示尚未分配，允许有意留空并保存理由。兵种存在不自动认领，非法兵种也不会抹去既定认领。每阶段记录支援触发、集合、撤退与不适用条件。删除玩家仅删除该稳定ID的记录与认领，不把后续玩家改成此人。

开放陆地4v4例子为本站整理；不是最强阵容，不输出胜率或必败判断。例子的建筑/升级完成是可修改的示例假设，实际兵力资源仍未核对。实际打开的来源及发布日、证据性质、2026-10-20核对日保存在手工内容文件：2021官方Two Pools地图说明、2020署名Teamgame Roles、2021官方论坛社区讨论。官方论坛观点不是开发者打法背书，网页旧数值不进入游戏资格。

## 完整分享与打印

URL为`项目base/team-plan/#/team-plan?version=1&plan=...`，完整UTF-8 JSON经base64url编码放HashRouter片段。`teamPlanShareUrl(plan, document.baseURI)`利用静态页的base元素还原部署项目根，清理外层search，不调用会把状态移到HTTP查询的`sharePageUrl`。片段不随HTTP请求发送，但不是加密；分享者自行决定分享对象。

全部阶段、未打开页签、中文/换行、名字、位置、前置、任务、空缺理由与当前阶段均入快照；不叠加sticky或本地存储。字段上限与HTML maxLength统一按UTF-16代码单元计；emoji占两个单元。名称24、位置48、标题/地图80、备注/留空理由120、协作说明160；每玩家每阶段最多8建筑、16形态、32研究。每条合法完整快照允许96KiB UTF-8 JSON及128KiB编码片段。上限不截断，全部合法字段填满的边界由专项测试核对；聊天软件可能有更小限制。

解码严查版本、参数键/重复、编码、UTF-8、结构、唯一性、安全整数与长度。损坏结构不显示默认已恢复计划，保留原参数供复制与显式重置；结构完整但实体、认领或确认语义错误时保留全部记录供修改。数据加载完成后才检查实体。复制失败显示完整手动链接。载入例子/重置产生可返回的历史项，普通编辑replace；前进后退按location完整恢复。

独立静态打印视图包含三个阶段的全部输入、完成记录、状态、空缺理由、协作说明与来源，允许多A4。屏幕输入和来源折叠不控制打印可见性；长文本自然分页。打印媒体使用`:root:has(.team-plan-page)`及更高优先级主题选择器覆盖深色根样式，仅使用现有语义令牌。
