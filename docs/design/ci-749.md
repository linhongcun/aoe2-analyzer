# #749 默认防坏门禁

授权：hongcun 于 2026-11-08 确认可做。范围只改日常 CI 的默认必跑集合，不改页面、交互或游戏数据。#659 的完整计划仍可由手动 full 跑到，但不再是 PR / main push 的默认。

## 默认必跑

普通 `pull_request` 和 `push`（含 main）：

| Job         | 作用                                                   |
| ----------- | ------------------------------------------------------ |
| `plan`      | 冻结窄门禁。不按 diff 风险把范围扩成 full              |
| `static`    | 现有 lint、typecheck、严格内容/来源/校验器/分层        |
| `build`     | `npm run build`，并只跑构建身份烟测（页脚版本与 HEAD） |
| `browser-1` | Chromium **单分片**窄冒烟，不可复用，对着本次构建跑    |
| `test`      | 聚合上述阶段。失败则不上传 `deployed-site`、不部署     |
| `deploy`    | 仅 main push，且 `plan` 与 `test` 都成功               |

窄冒烟固定为 `tests/e2e/smoke.spec.ts` 里的这些用例：

- 路由可加载且无控制台错误：首页、`#civs`、`#/civ/Franks`、`#unit/569`
- 查询：Ctrl+K 搜索 `paladin` 并打开单位页
- 计算：法兰克圣骑士满科技生命值为 192

缺任何一条，规划直接失败，不能靠少报用例放行。冒烟报告不是 `passed`，或 `browser-1` job 失败，聚合失败，`deploy` 的条件不成立。

## 仅 full / 手动

Actions → **CI / Deploy** → **Run workflow**，`full` 默认为 true。该次运行：

- `CI_FULL=true`，禁用阶段复用
- `static-main`（unused、contrast、必要时 introductions）
- 全部单测、`data` 重相位
- 构建内 24 条冷路由加身份检查
- `browser-1` … `browser-4`

这次运行**不部署**，也不上传给 Release 用的 `deployed-site`。把 `full` 设为 false 则只跑上面的窄门禁，同样不部署。

日更 `schedule`（`17 20 * * *`）已从工作流删除。代码里若事件名仍是 `schedule`，仍会走 full，避免以后把 cron 加回去却静默变窄。

`ci-probe.yml`、`ci-timing.yml` 不在默认 PR 路径：探针仍是手动/隔离分支，计时仍在 Release 完成之后。

## 不覆盖的风险

默认门禁拦得住：静态检查失败、构建失败、首页或上述关键路由打不开、搜索 Paladin 失败、这条圣骑士生命值算错、冒烟或聚合失败。

默认门禁**不**跑：其余路由、四宽、明暗、axe、整站 hash/表格巡检、Vitest、DAT/数据再生成、`static-main`。这些只在手动 full，或本地按需执行。`planChanges` 仍可在本地查看旧的消费者分类，CI 入口 `selectCiPlan` 不会用它扩大默认门禁。

## Release 产物

`test` 成功之后，main push 仍把 `${{ runner.temp }}/ci-build/dist` 上传为 `deployed-site`，Pages 使用同一目录。Release 仍按来源 run id 下载这个名字。来源 gate 必须带上窄冒烟标题和 `browser-1` 的 case id，且该 job 在本次 run 成功；多分片不能作为部署来源。
