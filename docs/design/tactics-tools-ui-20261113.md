# 对局与战术工具界面（冻结规格）

对应 #1004。五页独立设计复核工作流 `wfr-23fec44f67674a348fe6aad3c788394b` 曾通过首版样式规格，但用户认为变化不明显，要求以核心功能好用为目标大胆重构。用户于 2026-11-13 看过对局助手结构重排样板后回复“我觉得合适”，授权继续其余四页并按既有门禁发布。下述结构规格取代末尾首版 CSS 存档。

## 对局助手样板修订（优先于下方首版 CSS 限定）

- 核心任务：先选双方文明，再打开确实可用的练习；需要更多判断时容易找到三个独立战术工具。旧版当前对局纵向占据几乎整个桌面首屏，三个工具入口在长通用参考之后。
- 允许局部 `Matchup.tsx` 结构调整及 `matchup-pair.css`，不改 `RushDefense` 的计算/状态、任何 domain、URL、数据、共享壳层；使用现有 Icon 和设计令牌。
- 当前对局卡桌面分成左侧文明选择/开局与文明入口、右侧当前练习。DOM 顺序仍是输入在前、练习在后；<=900px 恢复单列。原有未选齐、无资格、待加载、加载失败/重试的内容与条件保留；未选齐时不创建新的空结果或确定性结论。
- 将已有三个静态工具链接从通用参考底部移至当前对局后、通用参考前，组成“战术工具”三区卡片；标题保持原链接主文本，增加简短用途说明与现有图标。保持原路由、不附加上方文明参数，清楚标出各工具需自行填写观察。桌面三列、手机单列。复盘与团队分工原链接留在该区下方的辅助入口行。
- 通用参考保留独立区块、所有公开来源、范围限制、单位反制和资格状态，不改成针对对方的确定性建议。早期应对与类型反制桌面并排、窄屏单列，避免宽页面长条正文堆叠。
- 练习入口改为显著的两张操作卡，保留动态文案、现有 href 和可用性 gating。不得把已有不适用警告隐藏到折叠区。
- 验证：新增本页布局回归（1280 默认输入/练习左右并排、战术入口先于通用参考；390 深色单列/不溢出/链接仍可用），保留既有默认对阵、切换打法、无资格及加载失败代表验证。检查现有 focus 和44px热区。只检查此样板相关文件；其余四页当前不重复验证。
- 桌面/手机“左：v0.77.92 原布局，右：样板未发布”对照已交付并获确认。可以继续实施整批、独立复核、专项验证和发布。

## 其余四页结构重排（最终实施规格）

### 共同边界

- 允许五页局部 JSX/CSS 和相关布局测试；不改共享壳层、domain、计算、生成数据、路由或分享协议。选择、加载、错误、锁定、清空、未知和示例的状态门控保持原样。
- 复用现有颜色、字号和间距令牌。主标题沿用现有样式，区块标题 `--fs-h3`（18px）/700，正文 `--fs-body`（16px），辅助正文 `--fs-sm`；卡片 `--radius-lg`、桌面 `--space-5`、窄屏 `--space-4`。44px 热区、focus-visible、数量 nowrap 保留。
- 360/375/390 使用单列；1280 使用各页下述布局，不强求相同模板。中间宽度用页面局部断点回单列，不把页面变成横向滚动容器。打印保留内容和现有隐藏/展开策略，不依赖屏幕两栏布局。
- 本次不删除功能；仅有意改变章节、表单分组和操作入口的呈现位置。旧首屏像素位置不是兼容合同，不能为保住旧位置恢复旧层级。

### 文明对比

- 核心任务先对照文明真实资料，再看主观评分。将现有资料对照整块移到选择器之后，主观评分性质、完整口径、分表和雷达作为后续独立区；评分摘要始终可见，不折叠或省略。
- 选择器组成双方身份卡，桌面并排并保留右侧复制/团队加成入口，手机两个文明仍同排、分享在下一行。资料表保留同排比较和双方颜色；不新增差值、胜率、结论。
- 主观分表与雷达仍桌面并排、手机单列；团队定位说明保留。更新旧“评分必须首屏”断言为“资料先于评分、摘要完整且可展开”，不删评分/来源断言。

### 侦察辨析

- 把情境、地图模式、阶段、计划移为全宽“选择情境与计划”卡；桌面情境独占首行，其余三项同排，窄屏一列。保持 DOM 内字段顺序、details 和 fieldset disabled。
- 下方左侧为“记录实际观察”，右侧为原解释/具体信号/待查/后续入口。观察卡、未知/未见/确认不存在/陈旧状态及可选时间范围保持完整。
- 桌面观察列约三分之一、结果约三分之二；信号内部的看到/含义/下一步保持已有分组。手机先选条件、再观察、再结果，不引入滚动锁定。

### 混兵情境

- 把情境、文明、时代移为全宽“选择对局条件”字段组；情境桌面占两份、文明和时代各一份，手机单列。
- 原主力、实际敌军、地图模式及情境专用字段留在左侧观察组，下方仍是观察细节和前置确认；右侧保留真实结果与示例的条件分支。
- 两个字段组都使用原 decoded.locked 门控，事件回调完全保留。长情境不再受左侧半列限制。结果卡按容器实际宽度自适应，避免右栏又强塞两列细卡；条件不足不得变成可采用结论。

### 城堡前置

- 五个当前观察字段改为全宽条件栏，桌面同排，中等宽度两列、手机一列；重置及查证提示仍在条件卡内，坏链 disabled 不变。
- 下方例子与阶段条全宽，当前重点与行动区桌面左右排列；行动卡在足够宽时两列，后续准备另起完整区块。窄屏按重点→当前行动→后续准备堆叠。
- 所有阶段、警告、代价、来源与 print 行为保留，不把准备混为当前可执行行动。

### 验证与发布

对局助手已通过 8 个专项、类型/lint/build；其余页新增直接布局断言，选现有默认/修改条件/分享锁定/打印代表用例，不跑整站矩阵。统一格式化变更文件、lint/build 各一次；已发现全仓 Prettier 的 179 个非样板文件问题，不做无关格式清理。实现完成后由独立代理核对最终 SHA、全部差异及供给截图；CI、main 部署、线上身份和正式 Release 同源产物核验通过后关闭 #1004。
