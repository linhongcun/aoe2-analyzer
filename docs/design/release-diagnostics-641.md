# Release 提前失败诊断 #641

基线 main：`6afacde268d80e4b7a1181046d6ef9aebaba78ab`。维护者已授权逐个处理剩余 issue；本项只改善失败证据，不推断 v0.74.3 那次未复现超时的根因。

## 范围与行为

- `scripts/deployment-smoke.mjs` 任一阶段失败时，在关闭浏览器前输出诊断，并尽可能写入 `test-results/deployment-smoke/diagnostics.json` 和视口截图 `failure.png`。已有 Release 的 `failure()` artifact 上传继续收集 `test-results`，无需修改工作流。
- 诊断包含期待版本和完整提交 SHA、失败阶段、当前功能/路由、当前 URL、原异常的名称/消息/堆栈、已观测 console error、pageerror、requestfailed，以及 JavaScript 资源响应状态。资源记录只取 URL、类型和状态，不取响应正文。
- 每类事件仅保留末 20 条，并记下总数/截断；消息和 URL 每字段最多 1000 字符，原异常堆栈最多 4000 字符，DOM 摘要最多 8000 字符。DOM 只提取可见正文、标题、页脚及主标题，不保存原始 HTML、脚本、表单值、Cookie、请求头或 storage。截图仅当前视口，不截整个长页。
- URL 去掉用户名/密码，并遮盖 search 和 hash 查询中 token、key、auth、password、secret、signature 等敏感字段；同一处理覆盖事件、DOM 摘要及异常文本中的 URL。日志与落盘使用相同的已脱敏内容。
- 页面或浏览器尚未创建、已关闭，或截图/读取 DOM/写文件失败时，仍输出可获得的结构化诊断，并说明缺失原因。诊断取证使用自己的短时限，不能无限拖住退出；它不改变产品检查的任何等待时间。
- 诊断自身失败不得覆盖原异常。已有失败时，清理失败也只作为次级信息；成功路径上的清理失败仍应失败。原异常对象原样抛出，CLI 保留非零退出码。成功路径返回值与输出含义不变，不生成失败证据。

## 失败用例与验证

新增 `tests/unit/releaseDiagnostics641.test.ts`，先只在旧 main 实现上运行，证明失败来自缺少真实诊断，而非缺新导出函数：

1. 本机受控页面先绘出可见页脚；一张延迟返回的图片阻止 load 完成。页面通过 rAF 确认页脚有尺寸，再记录 console/pageerror、卸载页脚并通知服务器释放图片。现有检查以原 10 秒断言真实失败；测试要求错误仍失败，日志/JSON/DOM/截图包含已观测证据、阶段和期待版本/SHA。
2. 受控 launch 失败、页面已经关闭、诊断目录不可写，以及主失败后 browser.close 再失败：均保留原异常，输出可获得证据，不靠重试转绿。
3. 正常受控页面仍返回 `['/']`，不写失败产物；CLI 在真实版本/提交不匹配时仍退出 1。
4. 使用虚构敏感参数验证 URL 脱敏及事件截断；不从执行环境读取任何凭据。

仅给真实失败测试足够的 Vitest 用例运行时间来容纳未修改的生产等待。若抽取辅助脚本，CI 只登记该精确维护路径并测试同名前缀/未知路径仍 full；新浏览器单测加入现有 Chromium 安装检测，不扩大目录白名单。独立复核规格和旧 main 红灯后再实施；最终执行实际维护计划、静态检查及构建一次，报告真实范围。
