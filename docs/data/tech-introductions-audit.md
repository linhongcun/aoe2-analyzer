## 首发口径

- 以当前具名科技首次引入为准，不继承文明首发、研究建筑年代或内部科技 ID 年代。旧文明也可能获得很晚才引入的科技。
- 仅修改效果、费用、研究时代、前置条件、适用单位或生产建筑，不重置首发。例如 Faith 原版已存在，后来新增前置 Devotion 不会让 Faith 也变成新科技。
- 旧科技被另一具名科技替换，或英文实质改名，按当前名字首次出现记录；保留前身与改名证据。例如 Bogsveigar 替换 Berserkergang，当前 Warships / Heavy Warships 的前身是 War Galley / Galleon 升级。
- 中文译名变化、大小写与拼写规范化不视为新科技。英文身份用于匹配来源，不能只按中文同名或别名匹配。
- 来源明确说明随某资料片首发、或属于其首发配套更新的科技，可归对应发行版本；不要求配套补丁与 DLC 发售在同一天。只由历史章节分期标题、拥有该科技的文明、或邻近日期推断的不成立。
- 独立免费更新单列 `update`。界面显示“免费更新 · 更新号”，筛选中与资料片、未标注分开；该标签不表示需要购买 DLC。
- 共享、区域科技也需自身引入证据。查不到可靠来源时用 `unverified`、`release: null`，不按其他文明或同系列科技补值。

首发配套的判断有明确公告依据：官方 [51737 公告](https://www.ageofempires.com/news/aoeiide-update-51737/)在公爵的崛起首发更新中新增 Hauberk；官方[海战改版预告](https://www.ageofempires.com/news/a-new-naval-warfare-in-age-of-empires-ii-definitive-edition/)明确改版随最后的酋长于 2026-02-17 上线，并逐项列出新科技。因此这两批按对应发行时期归档，与 Hul’che、Detinets 的首发配套口径一致；不会因它们也供旧文明免费使用就任意改为独立更新。

## 来源与限制

优先使用实际打开的官方发行、更新公告与开发商最初的资料片文明页面；seicing 文明和建筑的更新日志用于确认科技新增、改名及替换。基础科技对照 Microsoft / Ensemble 原版《国王时代》手册，其附录印刷页 110–111 及时代、防御升级章节包含科技名，来源链接保留 PDF 页码（比印刷页码大 5）。不把未能打开正文的搜索摘录当作完成核对。

来源只用于首发元数据，不采纳外站现行费用或效果覆盖本站固定数据。每条证据均为简短事实转述。明确已核实不等于来源永远不会变化；后续维护需重新检查对应具名身份。

## 可复现维护与回归

清单格式为 `schemaVersion: 2`。已核实科技须具有有效发行版本，或 `release: null` 加纯数字字符串 `update`；两者互斥。未知项只能 `release: null` 且不带更新号。单位、建筑的既有映射保留不变。

运行 `npm run introductions` 生成紧凑查表；`npm run introductions:check` 检查全部三种目录 ID、英文身份、数量、状态、来源、证据及生成结果。新增、删除、重命名科技，或漏登记、重复 ID、无效版本、猜测更新号都会使检查失败。CI 离线执行，不依赖外站可用性；运行时不请求外部历史页面。

科技列表、详情、筛选、测试 helpers 和运行时加载均使用同一套查表。回归覆盖国王时代索引 0、旧文明后来的独特科技、免费更新与未标注互斥、未知 ID、无效输入拒绝，以及 360 / 375 / 390 / 1280 两主题下的列表和详情。

#190 的科技保持原值测试仅约束其当时的范围，本轮由 #195 的来源清单回归替代；原单位与建筑测试、游戏数据和 `v0*-acceptance*` 验收期望均不改动。
