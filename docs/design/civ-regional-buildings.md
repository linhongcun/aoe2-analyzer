# 文明侧栏区域建筑（#456）

维护者要求在已确认的紧凑区域单位结构基础上新增区域建筑模块。此项只增加文明详情展示，不改生成数据、其它页面分类或建筑模拟计算。

- 位置：共用侧栏，独特单位、区域单位、区域建筑、快速入口；四个文明tab均可见。1280沿既有右栏布局，360/375/390沿既有布局排在正文后。正文不增加大模块。
- 外观：复用`SideBlock`、`uchips`、`ulink`和`BuildingIcon`，只显示标题、图标和建筑名称。字号、间距、圆角、底色、边框、浅深主题全部继承既有令牌；局部样式仅保证链接44×44px最小热区，不新增颜色或小字号。
- 数据：DE185872固定来源[aoe2techtree@3bb43b1](https://github.com/SiegeEngineers/aoe2techtree/tree/3bb43b1439eef88dfe7fe892d7f7dc41ac9dd76f/data/trees)的`RegionalBuilding`节点为1808骡车、1806强化教堂、1754商队旅馆、1889牧场、2556聚落。生成建筑目录未保留节点分类，因此纯查询用有来源的这五个ID识别类别，以输入的`Building.civs`筛选本文明真实可用项，不复制文明归属表、不按拥有文明数量猜测。下次更新DE来源时核对这一分类集合。
- 预期归属：亚美尼亚/格鲁吉亚两项骡车和强化教堂；印度斯坦/波斯商队旅馆；印加/马普切/穆伊斯卡/图皮聚落；契丹牧场。牧场虽只供契丹使用，上游仍标为`RegionalBuilding`，以实际节点分类为准。独特的城楼、大庄园、巨港、营垒、大商站，以及通用的炮塔/马厩等均不纳入。
- 链接：`/building/:id?civ=:civ&age=:age`，首先打开既有建筑概览，携带本文明和该建筑最低时代；切到科技模拟器及刷新保留这些查询参数。不更改建筑详情或模拟器实现。
- 状态：数据未就绪，一行`role=status`“正在加载区域建筑…”；确无可用项，一行“本文明没有区域建筑。”。切文明立即按新文明查询，不残留旧建筑。
- 验收：纯查询单测核对所有文明、全部五项、不可用/未知文明、普通/独特负例与只读性；端到端检查九文明内容、空态、受控延迟加载、tab/刷新、波斯商队旅馆链接及模拟文明，四宽×浅深主题截图、WCAG AA、44px、键盘和无溢出/错误。

本次不改受保护验收期望。现有区域单位测试和短烟测只迁移“快速入口”后的序号，保留其内容与行为断言；新增区域建筑烟测，沿用文明范围验证与同树发布证据复用。

数据审计补充：独立代理逐一读取固定上游全部56棵树，确认五项分类集合与生成建筑的文明归属完全一致。本地`trees.json`省略无grid的商队旅馆和牧场，不能用它验证这两项；单测对三个有grid的建筑补充交叉验证，对五项全量使用已核对的归属矩阵及原建筑可用性。

实施前核验：36b0668基线的1280浅色端到端用例实际失败于侧栏缺少“区域建筑”，无页面运行错误。独立代理`regional_buildings_review`预审规格及失败用例，指出本地树应检查建筑列头而不是单位/科技状态键；修正后预审PASS。实现后的实际SHA、四宽截图与适用检查结果记录在PR。
