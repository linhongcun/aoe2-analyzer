# 项目功能整合交互设计提案

状态：维护者已确认交互方向并授权实施；正式系统改造范围见[实施规格](IMPLEMENTATION.md)与 [#531](https://github.com/linhongcun/aoe2-analyzer/issues/531)，发布状态以对应 PR 和 Release 为准。日期：2026 年 10 月 30 日，Asia/Shanghai。原设计现状依据代码提交 `4b23f8cf1648a50508b438cf76cf8e2b45ffecb8`。

现有站点已经能从文明进入开局、生产和对局，也能在对局、单位 PK 与开局之间进行部分往返。下一步的价值在于让玩家继续探索时保留条件，并把不同工具的结果接成可验证的行动。保留现有页面和轻编辑视觉，通过统一情境条、明确的参数带入和结果区的下一步入口，完成三条任务路径。

[查看可点击交互原型](index.html)。原型覆盖单位资料、持续生产、经济科技收益三屏，复用现有生产和收益计算器，并以原型自己的 hash 查询保存状态。其余路径属于完整方案的设计范围，不表示已经在原型中实现；原型参数也不是新增的正式生产协议。

## 已有能力与需要补齐的交互

本提案接续 [站点串联信息架构](../site-linking-517/site-linking-517.md)和[查文明情境入口](../civ-context-521.md)，不将已实现的第一轮串联重复作为待开发功能。旧协议、旧计算规则和旧规格中未被本提案明确更新的部分继续有效。

## 三条任务路径

### 对阵验证

1. 玩家在对局助手选定双方文明，查看适用范围与建议依据。
2. 从某条具体建议进入单位资料或 PK；情境条显示原对阵，结果区列出所用时代、单位、科技和团队条件。
3. 玩家调整条件后重新计算，再选择“按 A 方规划生产”或“按 B 方规划生产”。A 和 B 是 PK 的两侧，入口不能默认认定 A 就是玩家自己。
4. 生产工具展示带入预览，核对单位资格与生产地点，玩家填写建筑数量后计算持续供给。
5. 玩家可以原样返回 PK，也可以回原对局；在复盘页记录仍需验证的问题。

文明对比页增加“以左侧为我方分析”和“以右侧为我方分析”，明确将对称的 A/B 转成有方向的 `me/opp`。科技树差异对比需要单独补齐可分享的对方文明和显示模式协议，不能依赖某个浏览器已有的 sticky 选择。

### 兵种生产与经济

1. 从单位模拟器或 PK 的已选一侧进入持续生产，保留该侧文明、时代、单位以及生产工具能够解释的科技。
2. 填写专用生产建筑和数量，得到各资源持续消耗与供给人数估算；先说明这些是模型需求，不代表玩家已有经济。
3. 从某种资源的结果进入经济科技收益，保留兼容的文明、时代和已研究科技。玩家选择目标科技，填写实际采集人数，或明确选择“用供给估算作为假设人数”。
4. 收益结果分别展示研究投入、研究时间、固定人数下的增量和适用限制。玩家返回原生产配置，主动切换科技假设后比较两份结果。
5. 需要黄金供给时沿用已有“按当前生产金耗规划商路供给”；市场、圣物仅作为各自模型的补充，不能直接与其他工具相加生成未经统一口径验证的总收益。

这条路径回答的是“这种配置需要怎样的经济支持”。它不认证资源足够、建筑已完成、科技已研究或实战能够持续生产。

### 查资料到练习

1. 从文明进入科技树，再点单位、科技或建筑，保留当前文明；详情同时解释本文明是否可用。
2. 从单位进入模拟器，或从文明进入开局，先理解当前条件下的变化与限制。
3. 开局中的“暴经济”“转骑士”只更换路线；距离、自动房屋和文明等兼容条件保留。路线变化使旧步骤失效时，回到新路线起点并提示，不能把旧步骤编号当作等价阶段。
4. 使用已有专注跟练或打印步骤单，继续保留开局条件和来源链接。
5. 以“记录一个练习问题”进入复盘页。玩家填写触发情境、想做的动作和观察标准，沿用现有单一练习目标及自报结果，不自动生成能力分或成功率。

后续可增加“用当前步骤检查后续生产”，但必须先展示该步骤的模拟快照及时间点。开局中的库存、村民和已完成建筑属于模型状态；不能直接认定为玩家当时的真实局面，也不能把尚未完成的建筑当成可生产建筑。

## 现有功能如何进入任务路径

首页和导航继续从 `pageRegistry` 派生，沿用已有分组和搜索。以下是功能之间的分工，不建立另一份路由登记表，也不要求每页堆满全部工具入口。

| 功能范围                                                     | 在任务中的作用             | 关联交互及边界                                                                                           |
| ------------------------------------------------------------ | -------------------------- | -------------------------------------------------------------------------------------------------------- |
| 文明、单位、科技、建筑、科技树、文明加成                     | 核对资格、来源和机制       | 带当前文明进入详情与模拟；建筑详情关联施工、生产和适用驻军工具；缺少目标资格时保留资料查询能力           |
| 文明对比、对局助手、科技模拟器、单位 PK                      | 比较条件并验证局部效果     | 明确双方方向与当前假设；将适用单位接到生产，不把局部模型结果提升为整局胜负                               |
| 开局流程、跟练、打印                                         | 从理解步骤到有条件地练习   | 方案切换保留兼容条件；练习问题进入现有复盘，路线和数据支持缺口保持可见                                   |
| 持续生产、经济科技收益、商路、市场、圣物、多人施工、驻军回血 | 估算资源与时间投入         | 结果旁给有针对性的下一步；不同时间尺度、资源口径及人口假设不得未经核对直接相加                           |
| 侦察辨析、混兵情境、城堡前置应对                             | 解释观察并核对行动前置     | 只带目的工具支持的文明、地图和阶段；未知、陈旧、未覆盖分别保留，进入前置工具不代表已确认威胁             |
| 团战分工、队伍加成                                           | 约定队友职责，解释加成来源 | 队伍选择可以作为来源，分工仍需玩家填写；不能把两个对手文明自动放到同一队                                 |
| 一局与观赛、术语、时间换算、快捷键、战役入门                 | 为当前任务补解释与操作准备 | 在疑难词、时间和步骤旁提供定向帮助，返回原任务；游戏时间与视频时间不互相推算，战役条件不套用随机地图模板 |
| 地图资料                                                     | 决定场景能否使用某类建议   | 只有目标工具明确覆盖该地图和模式时才预填；其他情况说明未覆盖，不能将地图名称近似匹配为已支持             |
| 职业选手、赛事、文明职业视角                                 | 提供有日期和范围的观察材料 | 有稳定实体 ID 的选手、赛事和文明可互链；展示收录日期与范围，历史比赛不直接变成当前版本战术证据           |
| 版本补丁、更新历史、数据说明                                 | 解释结论使用的数据口径     | 从受影响实体查看变更并返回；资料版本与玩家实际比赛版本分开，历史演示保持原版本标识                       |
| DLC、内容与购买                                              | 解释内容归属和获取方式     | 从文明或战役查看关联内容；历史首发、当前购买包和模拟器资格分别解释，不将购买建议混入战斗结论             |

复盘是练习记录的落点。首页仅帮助开始任务，搜索保留直接查实体的效率；不要求用户先建立一份全局对局档案才能使用计算器。

## 情境与结果的共同结构

### 区分导航情境和工具输入

导航情境包括当前文明、原对阵双方、上一工具来源和回程地址。工具输入包括单位、时代、科技、建筑、观察与采集条件。复盘内容则属于玩家草稿。三者独立校验，不能因为导航中出现某个文明，就把未填写的军队、地图或已研究科技补成事实。

当前工具中用户明确选择的条件优先于带入值；合法完整的目标 URL 优先于上次本机选择。继续保留旧工具现有的首次访问默认值与容错规则。新进入的页面不能用 sticky 静默覆盖合法带入，也不能把未知条件显示成“已确认”。

### 情境条

位置沿用现有 `ctx-bar`：标题下、标签页或主要参数区上方。桌面端一行自然换行，手机端主回链单独占一行，文明与其他入口接在其后。

- 有上一工具时显示“回单位 PK”“回持续生产”等具体文案，并恢复进入前的完整有效配置。
- 有原对阵时显示“原对局：蒙古 对 中国”，提供真实链接。当前工具的文明改变后，原对阵仍保留原双方，不能跟着改写历史来源。
- 当前文明使用可点击的文明名；存在不同来源文明时，明确写“当前文明”和“原对局”，避免同一排未标注的名称造成混淆。
- 一条主要后续操作紧邻结果，例如“按 A 方规划生产”；其他工具放入“相关工具”折叠区。折叠区只负责导航，不代替页面标签。
- 直接进入且没有来源时，不展示虚构的“返回”；现有首页、目录入口继续可用。

情境条是局部辅助导航，不新增全站任务向导或独立总览页，也不扩张顶栏导航名单。

### 每个结果都回答四件事

| 区域       | 内容与交互                                                                         |
| ---------- | ---------------------------------------------------------------------------------- |
| 结论       | 用一句话说当前输入下能判断什么；已有具体计算结果时使用该结果，无结果时说缺少什么   |
| 条件       | 将时代、科技、人数、距离、观察状态等关键条件放在结论旁；每项可定位到现有设置       |
| 依据与限制 | 给出来源、数据版本和已计入机制；未建模影响若会改变解读，直接贴近结论，长资料再展开 |
| 下一步     | 根据当前有效结果提供一条主要操作和少量辅助入口；写明将带入的条件及仍需填写的条件   |

文明能力评分、社区战术资料、数值模拟、玩家观察分别标明性质。可以并列“本模型中的战斗结果”和“相同假设下的持续供给需求”，不能据此生成胜率、最优阵容、保证可执行的建议或自动败因。

### 串联后新增的信息价值

| 关联的功能                 | 玩家可以进一步回答的问题                                       | 呈现方式                                                                                 |
| -------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 同一生产方案的两种建筑数量 | 多开一座建筑会增加多少资源压力？                               | 原型固定文明、时代和采集条件，演示总供给人数与人数差；正式切片再并列逐资源消耗及人数差   |
| 持续生产与经济科技收益     | 在明确的人数假设下，科技增加多少供给，投入多久达到等采集平衡？ | 保留原方案，区分研究成本、增量和时间；原型已经演示                                       |
| 单位 PK 与持续生产         | 某种战斗表现需要付出怎样的持续经济投入？                       | 同条件展示局部战斗结果与生产需求，分别注明双方科技，不合成“最佳兵种”评分                 |
| 生产与商路、圣物           | 一种黄金来源能覆盖当前方案多少需求，还差多少？                 | 商路沿用已有生产来源机制；圣物作为后续切片，数量由玩家填写，口径核对后再显示覆盖率       |
| 开局步骤与后续生产         | 到达这个模拟时点后，哪些后续条件还需要补齐？                   | 显示时间点、已完成建筑与稳态需求的区别；食物来源不等价时分别列示，不能直接相减为实战缺口 |

这些问题由玩家当前选择触发。入口和结果说明围绕具体问题展开，避免用户自行拼接多个工具的数字。

## 开局和经济的带入规则

### 开局内部切换

“查看全部开局”保留合法 `civ`、原对阵和回程来源，去掉当前路线的 `bo/step/view`。列表重新进入路线时沿用现有克隆参数方法，随后验证该路线支持的条件。

“暴经济”“转骑士”保留合法文明与两条路线都支持的模拟设置，只更新 `bo`，清除不再等价的步骤和跟练位置。若路线无法建模本文明，保持文明选择并显示现有通用示意或不支持状态，由用户选择其他路线；不能切到另一文明后继续显示原文明名称。

跟练、打印和复制链接基于同一份当前开局设置。打印省略交互控件，但保留文明、路线、假设和来源地址。

### 科技资料进入收益

有合法当前文明时，收益入口携带该文明和目标科技。现有 `age` 仍表示计算时代；资料中只知道科技解锁时代时，注明“按科技解锁时代开始设置”，不声称这是玩家当前时代。来自已有模拟器的时代则沿用并校验。

目标科技在本文明自动免费、已研究、不可用、时代不足或当前收益模型不支持时，分别展示原因。自动免费已获得与玩家手动研究分别标识，均不重复计算研究投入。无文明来源时，目标页允许使用现有默认文明，但在带入说明中写清这是默认值。

### 持续生产进入收益

在离开生产页前或进入收益页后，展示同一份带入预览，不增加重复确认步骤。

| 字段                 | 带入方式                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| 文明与时代           | 自动带入并按目标资格校验                                                                               |
| 已研究科技           | 仅带收益模型能够表示的经济科技，目标页继续校验前置规则并提示缺失项；不兼容项目列明未带入               |
| 采集距离             | 按资源和模型含义核对；生产的农田距离与木金石距离不能压成一个值后称完全保留，无法等价时要求选定收益假设 |
| 采集人数             | 默认留给玩家填写；可明确选择以当前生产所需的供给人数作为假设，并持续标注“供给估算”                     |
| 目标科技与观察时长   | 由玩家设置，不根据资源缺口自动认定某项科技最优                                                         |
| 生产需求、建筑与数量 | 作为来源快照保留，供返回恢复；不混入收益模型的固定人数参数                                             |

返回生产时恢复进入前的原配置。收益页新增研究不自动写回生产配置；玩家通过“用这项科技作生产假设”主动打开一份变更后的配置，并可看到变化项。这个操作不代表游戏内已经完成研究。

### PK 或单位进入生产

先明确选择哪一侧，再使用目标工具现有的参数编码。带入单位、文明和时代；科技必须以目标生产工具实际支持范围映射。战斗科技不能一律作为经济科技；其他盟友加成在目标模型未支持时列为未带入。

PK 的军队数量不等于生产建筑数量；结果中的采集时间预算也不等于持续生产中的实际村民分配。建筑和数量未确定前只显示待配置，不输出“已达到目标兵力”。

天梯数据目前是规划占位，没有可直接用于分析的现成统计数据；未来取得可靠来源后再单独设计统计入口与样本说明。

## URL 和多跳回程约定

以下新增协议属于提案，实施时需添加编解码与回归；原型内状态不代表正式路由已经支持。

| 字段                    | 约定                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------ |
| 既有 `civ`、`bo`、`tab` | 保持目标工具现有含义；不改名、不复用为其他对象                                                   |
| 既有对局 `me/opp`       | 保持原对阵方向；单方资料的 `civ` 可以不同，不用它反推原双方                                      |
| 既有 PK `a/b` pack      | 完整保留单位、文明、时代、科技等原编码，不改成纯文明参数                                         |
| 既有对比 `a/b`          | 继续为对称文明选择；转换到对局时由明确的“以哪侧为我方”操作确定方向                               |
| 既有 `from`             | 保留已支持值和含义；只说明来源类型，不承担完整配置恢复                                           |
| 新增 `ctxReturn`        | 编码上一工具的站内路由及有效查询，去掉其自身 `ctxReturn` 后写入；用于恢复上一工具配置            |
| 科技树模式与对方文明    | 另增经过规格化的可分享字段，沿现有单方 `/tree/:civ` 路径扩展；不在本轮原型中伪装成已支持正式协议 |

多跳采用“上一工具快照加原对局”，不将所有历史递归塞进 URL。例如对局进入 PK、PK 进入生产、生产进入收益：收益回到生产；生产仍可凭原对阵入口回助手；浏览器后退保留正常逐页路径。若直接打开分享链接，`ctxReturn` 提供上一工具配置，`me/opp` 提供原对阵入口，不声称还原未携带的完整浏览历史。

`ctxReturn` 只接受本站已登记路由的路径与查询，禁止绝对外站 URL、协议、`//`、上级目录及嵌套 `ctxReturn`。用结构化参数编码，按工具现有上限处理长度，不能截断后宣称分享成功。来源失效时保留当前有效计算，隐藏不可执行的回链，并提示“来源链接不可用，当前设置已保留”。

严格参数工具需先单独校验并分离新增导航字段，再将原工具输入送入既有解码器；写回时重新附加合法导航字段。不能通过放宽未知键、重复参数或原计算校验来支持新情境。保留各工具既有未知参数合同，尤其文明对比的重复未知键及相对顺序。

同页控件的小幅编辑沿用现有 `replace` 规则，跨页导航和明确打开新假设进入历史记录。带入来源是快照；后续修改当前页不追溯更改来源，避免回程时得到一份没有见过的配置。

## 复盘草稿的衔接

“记录一个练习问题”进入现有复盘页，提供来源预览，而不是新建复盘系统。可带入明确的原双方文明、来源工具链接和玩家主动填写的问题。游戏版本、地图、录像时间、实战事实不从本站当前数据版本或模拟器时刻推断。

空草稿可由玩家一次选择“加入本次问题”。已有草稿时显示拟补充内容与目标字段：仅空字段可以主动补入；已有内容保留。新增事件沿用稳定 ID 和数量限制，已有唯一练习目标不自动替换；玩家可以取消并继续原草稿。

复盘编辑、存储冲突、损坏备份、导入预览和恢复沿用既有规则。来源链接由受控站内路由生成合法 HTTP 或 HTTPS 地址后写入现有链接字段。正文和疑问留在本机草稿，导航查询与公开页面元数据不写入自由文本；复制摘要或备份仍由玩家主动发起。

| 状态                       | 页面行为                                                               | 下一步                           |
| -------------------------- | ---------------------------------------------------------------------- | -------------------------------- |
| 没有来源                   | 使用直接访问路径及原默认设置，不显示虚构回链                           | 选择条件开始                     |

| 无效目标参数               | 沿用原工具的错误与暂停计算规则，保留可修正输入                         | 主动修正或重置                   |
| 无效来源参数               | 不影响已验证有效的当前工具输入，关闭错误回程链接                       | 保留当前页，使用现有导航         |
| 数据加载中或失败           | 加载时说明所需资料；失败显示重试且保留当前设置，不输出旧结果冒充新结果 | 重试或回来源                     |

| 通用开局示意               | 保留原免责声明，不称本文明的已验证专用开局                             | 继续查看假设或选择其他路线       |

| 原条件已变                 | 已存快照标明来源条件；显式打开变更假设，旧结果不继续显示为当前结果     | 重新计算或回原配置               |
| 复制失败或链接过长         | 明确失败，保留完整可复制内容；不发送、不自动截短                       | 手动复制或使用原工具已有导出能力 |
| 草稿已存在或其他标签已修改 | 预览待加入内容；按原存储冲突规则暂停写入                               | 取消、选择补入或保留本页草稿     |
| 存储不可用或导入损坏       | 当前输入和原草稿都保留，不显示已保存                                   | 复制备份或主动恢复               |

## 手机端和键盘操作

沿用现有设计令牌、Lucide 图标与浅深主题；正文最小字号和触点按项目规范执行。新增可点区域至少 44×44 px，文字不小于 12 px。数值与单位使用 `.num` 或 `.nw`，不能在窄屏拆开。

在 360、375、390 和 1280 宽度核对情境条、带入预览和结果下一步入口。页面没有横向滚动；科技树和宽表格保留其明确标注的局部滚动。重要限制紧邻结论，不只放页尾。

导航使用真实 Link，支持复制地址、中键与新标签。Tab 顺序跟随视觉顺序；当前页和折叠区有明确语义及可见焦点。若带入预览使用弹窗，打开后聚焦标题或首个操作，Escape 关闭并把焦点还给触发入口；错误定位到具体字段，复制和保存反馈使用 `role=status`，需要立即处理的错误使用 `role=alert`。

分享包含当前有效输入与受控回程来源，刷新后结果和情境一致。新标签不能依赖原标签内存才能计算；已填写的复盘自由文本不随来源链接公开。普通页面的分享和打印不声称包含未导出的本机草稿。

## 小切片实施顺序

以下是实现候选顺序，不代表已经建立或认领 issue，也不改变当前发布版本。每个切片以单独范围评审，沿现行独立代理复核和适用验证流程交付。

| 顺序 | 切片                       | 完成条件                                                                                                  |
| ---- | -------------------------- | --------------------------------------------------------------------------------------------------------- |
| 一   | 开局内部情境保留           | 两条城堡后路线、返回列表、重新进入与跟练打印使用同一文明和兼容设置；原对局回链持续存在                    |
| 二   | 科技资料的收益入口         | 科技入口不丢已有文明；明确默认时代、不可用、免费和已研究状态，不自动填采集人数                            |
| 三   | 导航情境的受控回程协议     | 新增 `ctxReturn` 编解码和通用情境条，先用生产与收益间的配置往返验证，再接 PK 和开局；原协议和严格校验保持 |
| 四   | 生产到经济收益             | 展示带入预览，人数与距离含义明确；能恢复原生产配置，主动采用科技假设才打开变更配置                        |
| 五   | 单位与科技树继续探索       | 对局“用本文明模拟”、文明到特色单位、科技树到单位与科技均保留合法情境；不支持时有明确状态                  |
| 六   | 从局部验证到生产           | PK 明确选侧，单位资格与科技映射可审查；建筑数量由用户填写，不能误用军队数量                               |
| 七   | 资料与演练进入练习记录     | 来源预览、空字段补入、已有草稿保护和取消均成立；保留单目标与自报结果模式                                  |
| 后续 | 更多战术工具和开局步骤快照 | 先核对地图、模式、时代及观察语义，再按各自规格接入；不把文明识别替代侦察事实                              |

第一、二切片可先使用既有文明和原对阵参数，在第三切片补完整多跳恢复。第一、二切片不得提前生成尚无解码器支持的 `ctxReturn`；界面也不展示尚未成立的“回原配置”。

## 验收场景

1. 从同一对局进入我方开局，打开“转骑士”，再“查看全部开局”并进入另一条路线；当前文明和原对局方向保持，失效步骤明确重置。
2. 直接带合法文明访问经济科技详情，点击收益；目标页显示同一文明及目标科技。不可用、免费、已研究与时代不足分别可复现。
3. 在生产页设置一份非默认配置后进入收益，未经选择不将理论所需村民认作实际人数；主动选择供给估算后，有清晰假设标记。
4. 修改收益条件并返回，原生产需求、建筑数量、时代和科技完整恢复；主动打开新增科技假设时才创建对应配置。
5. PK 到生产必须能分别选 A 或 B。任何一侧均以该侧真实单位和文明带入，军队数量不写为建筑数量。
6. 对局推荐单位的名称入口和模拟入口都能回到同一 `me/opp`；切换单位普通与精锐、详情标签后仍保留必要情境。
7. 文明到科技树再到单位或科技，详情显示同一当前文明；资格不成立时保留名称并说明不可用，不自动换为另一文明。
8. 多跳链接复制到新标签并刷新，可恢复当前有效配置、上一工具快照和原对局；不依赖原标签 sticky 或内存。
9. 无效或过长回程来源不执行外站导航，不清除当前有效配置；工具自身无效参数继续按原规则阻止不可信计算。
10. 对比页选择“以左侧为我方”后方向正确；保留原对比未知参数、历史和复制合同。
11. 复盘已有正文、事件或目标时，取消来源补入没有任何写入；确认仅修改所选允许位置。跨标签冲突和存储失败不丢原草稿。
12. 四宽、双主题、纯键盘、新标签、复制失败和加载失败均能完成对应路径；没有页面横向溢出、控制台错误或页面异常。

实现前针对实际切片补能暴露现有断点的失败场景，计算映射新增时配必要领域单测。复用旧金标准与受保护验收，不通过放宽期望达成结果；检查范围按实际改动风险选取，不为设计提案运行数据重生成或全站发布。

## 交付范围

本轮交付交互规格和可点击原型，用于评审功能之间的关系、带入规则与状态。正式产品后续按切片实现并独立验证。维持现有数据来源、计算公式、路由骨架和轻编辑视觉，不加入自动最优推荐、胜率预测、遥测采集或未经授权的外部发送。
