## 已决定的首版契约

采用**记录用户确认的前置状态**，不实现完整研究链模拟。两个模块各自保留薄 wrapper，直接复用 production 与既有固定形态索引，无需新增共享运行时模块或数据 pipeline。

- production 仅证明潜在文明、时代、生产地点及既有解锁入口，不能证明用户已研究、已建造或资源兵力充足。
- completedForms 是用户逐项确认“实际已完成该精确形态所需升级”的事实声明，包含本形态所需的前置升级。选择一个单位本身绝不生成该确认。
- 已经免费获得的升级也须用户确认实际完成；不根据现有免费清单替用户打勾。
- completedUnlockTechIds 独立记录化学等必要解锁是否实际完成；completedBuildings 独立记录当前可用的已建生产建筑。
- 不自动研究，不自动建造，不把 effectiveProductionTechs 自动补出的前置或免费项当成用户确认。
- 结果称“所列前置已满足”，不用“研究链已完整核对”“当前已就绪”等扩大承诺的文字。
- 同一阶段确认了更高形态却仍选择低形态时，要标明“已被升级取代”或要求调整，不能把低形态列为精确当前可训练。
- 形态索引缺失且无法确认是无需升级的基础形态、未支持的特殊解锁或池外单位，返回 unsupported，不能默认条件满足。

这满足两个 issue 中“记录形态及前置状态”的语义。它不宣称系统独立验证了玩家填报的完整研究链或免费规则，不能在实施文案中重新引入这些承诺。

## 接口建议

各模块可自有实现，字段语义、主状态和边界样例一致即可。白名单及事实来源不能在两个模块各复制一份手写游戏规则。

```ts
type UnitPrerequisiteStatus = 'age-unavailable' | 'civ-unavailable' | 'missing-prerequisites' | 'unsupported' | 'conditions-met';

interface UnitPrerequisiteInput {
  civ: string;
  age: 2 | 3 | 4;
  unitId: number; // 精确形态
  completedForms: readonly number[]; // 独立确认：所需形态升级实际已完成
  completedUnlockTechIds: readonly number[]; // 独立确认：化学等解锁实际已完成
  completedBuildings: readonly number[]; // 独立确认：当前可用的已建生产建筑
}
interface UnitPrerequisiteResult {
  status: UnitPrerequisiteStatus;
  potentialBuildingIds: readonly number[]; // 数据上潜在合法地点
  confirmedBuildingIds: readonly number[]; // 与用户已建建筑的交集
  missingFormIds: readonly number[];
  missingUnlockTechIds: readonly number[];
  missingBuildingAlternatives: readonly number[]; // 可选一个，非要求全建
  reasons: readonly { code: string; entityId?: number }[];
}
```

输入校验和资格校验分开：

1. 未知文明、NaN/越界时代、未知单位 ID、未知字段 ID、损坏 URL 等返回 decode/validate errors；不伪装成“暂未覆盖”，不静默回退默认文明。
2. 已知单位池外、数据规则未支持 -> unsupported。
3. 池内但最终静态文明资格不成立 -> civ-unavailable。
4. 此文明能使用但时代未到 -> age-unavailable。
5. 形态完成确认、必要解锁确认或至少一个合法生产建筑确认缺失 -> missing-prerequisites。
6. 以上条件满足 -> conditions-met。

可保留多个 reasons，但主状态有固定优先级。年代不足与缺科技不能都压成“当前不可用”。有多个合法地点时，用户只需确认其中一个已建；不能要求全部地点都完成。

潜在查询可以使用反事实配置：该文明/当前时代所有合法生产解锁，仅用于判断“如果前置满足是否可能”。其返回值和 effectiveProductionTechs 结果均不得写入 completed*。实际缺失解锁仍由 completedUnlockTechIds 原样独立检查；土耳其自动免费化学也不跳过用户实际完成确认。

基础形态无需虚构升级；对有升级的形态必须有独立 completedForms 确认。garrison.unitUpgradeTechs 可用于识别候选升级形态，但不存在索引不等于证实没有前置。对冻结白名单先做静态完整性核对；未核实条目暂停。

completedForms 的“高阶已完成”足以判定同一普通升级链低阶形态被替代，但不能回写低阶确认作为新的用户勾选。家族/祖先关系可以复用 units.from_ / 现有 family，不能把 sibling 当彼此替代。遇到与普通 from_ 链不一致的特殊路线，显示 unsupported 或明确人工修正，不猜测精确生产名录。冲突建议返回独立配置错误 superseded-shape，保留原选择并要求修正，不塞进“尚缺前置”，也不显示条件满足。

#243 每位玩家、每个时代的 completed* 独立保存/分享，禁止合并同队玩家或其他阶段的完成状态，也不自动认领战术任务。#241 只有前置成立的分支才可列为当前有条件采用；条件成立不证明阵容克制或资源负担可承受。

中文说明建议：“按固定数据和你确认的形态升级、解锁及生产建筑完成状态核对；未核对资源、人口、兵力或实际支援。”

## 为什么不直接复用现有科技链

- src/domain/production.ts:150 的 productionBuildings 已核对文明树、目录文明、eco.units.at、建筑/单位时代、提前解锁和化学等入口；适合复用潜在资格，无须复制 earlyUnits、化学名单和生产地点表。
- src/domain/production.ts:118 的 effectiveProductionTechs 自动补 Tech.pre 并加入免费生产科技。它服务生产规划，不能当作用户完成集合。
- productionTechs 只开放经济/生产相关具名科技；大多数单位形态升级不在 techs.json。
- scripts/garrison_general_build.py:203 仅为 techs.json 具名科技导出规则，:219 的 unitUpgradeTechs 则扫描所有可研究升级。两者覆盖范围不同。
- 例：弩手 24 -> 科技100、劲弩492 ->237、重骑283 ->209、长戟359 ->429；这些升级 ID 不在 techs.json / garrison_general.techs。不能从当前 Tech.pre 求完整链。
- raw237 是 2-of [103,100]；429 是 2-of [103,197,956]；209 是 2-of [103,166,768]。不能把所有依赖一律作 AND，或只按目录时代替代 n-of。
- 冠军剑士567 映射 [264,1174] 两种路线，不是都要研究；原始分别为 2-of [103,217,954] 与 3-of [103,207,1138]。选择“形态所需升级已实际完成”可以表达用户事实，但现有导出不能独立模拟这两条研究链。
- garrison.civs.Turks.free 仅有具名科技47，漏掉原始科技树中免费254轻骑、428翼骑。埃塞自动规则590 免费197长枪、保加利亚693 免费222/207/217，也未完整进入现有免费清单。
- docs/data/garrison-general224.md 已说明 unitUnlockTechs 只是原始启用命令，不是排他强制前置。不能把该表直接变成全部单位解锁要求。
- src/domain/garrisonGeneral.ts:211 的 implicitShapeTechs 是驻扎“已经有此形态”的假设，不能证明计划单位升级已完成。
- productionBuildings 不会因为高级升级完成而移除旧形态：轻骑升级后仍返回斥候骑兵马厩。因此高级/低级冲突必须由新 wrapper 单独拦住。

如未来要把上述用户确认升级为自动研究链校验，届时才需要固定导出：方向明确的升级边、相关科技依赖闭包/n-of/文明研究地点、自动免费费用时间规则及其触发条件。首版不新增这一 pipeline，也不在文案宣称它已经实现。

## 必要边界样例

无需为本次只读审阅跑全套。实现时补少量领域表格用例，并在两个模块各验证保存/恢复即可：

1. 阿兹特克骑士 -> civ-unavailable；法兰克封建骑士 -> age-unavailable。
2. 不列颠城堡弩手：只有选择单位仍缺形态确认；已确认形态但未确认靶场，仍缺建筑；两者明确确认后才 conditions-met。
3. 波希米亚城堡火枪：47 未确认 -> 缺前置；47 与靶场都已确认 -> 条件满足；普通文明城堡火枪 -> 时代未到。
4. 土耳其轻骑/翼骑或免费化学、埃塞长枪：不因文明/时代/旧 free 清单自动确认；用户明确完成后才能解除对应提醒。
5. 亚美尼亚提前长枪/长剑、勃艮第城堡重骑、库曼封建攻城锤：复用 production 的时代例外，但形态及建筑确认仍独立。
6. 选择弩手时不能自动勾选完成形态；选择已确认劲弩后不能在同一状态下把弩手列为精确当前可训练。冲突保留原选择、给调整提示。
7. 多地点任选一个合法已建地点；错误建筑 ID、未来时代建筑或本文明不合法地点不算完成。未支持特殊解锁与池外形态明确 unsupported。
8. completedForms/解锁/建筑在刷新、分享链接中分别往返；坏参数不默认为全完成；不同玩家/阶段状态不串用。
9. 形态资格与任务认领独立：无某形态不等于任务无人认领；有某形态不自动认领反制/支援；conditions-met 不输出人数、胜率或保证。
10. 最终39白名单逐项核对：基础/升级分类、升级索引存在性、生产潜在地点、from_ 祖先关系。无法核实的一项明确 unsupported，不以空映射当基础形态。

待实现完成后可据以上契约再做独立只读审阅；首版不需要为记录前置状态实现完整研究引擎。
