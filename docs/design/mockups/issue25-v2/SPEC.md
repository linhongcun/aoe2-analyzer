# #25 PK 盈亏平衡点 · 交互规格（Jony）

口径（Steve 已定）：B 固定数量默认 10、可改；A 的搜索上限 200；胜负规则与主 PK 群战（集火模型）完全一致。

## 入口
- `N vs M` 结果卡内，结论下方放主按钮「算盈亏平衡」，旁边 muted 一行「A 至少要多少个才能打赢 B × {M}」。
- 1v1 和等资源模式不放入口（v1）。
- B 数量就是 N vs M 里 B 的数量（默认 10），改了以后需要重新计算。

## 计算中
- 结果卡内显示进度条 +「已试到 A × k / 200」+「取消」；不要整页转圈。

## 结果
- 大号琥珀数字 N（64 / 移动 48）+「个{A}，才能打赢 {M} 个{B}」。
- 参数摘要一行：文明、单位、B 数量、科技预设、模型。
- 三档表：N − 1（负）/ N（胜，浅琥珀底高亮）/ N + 1（胜）；列为 A 数量、结果、A 剩余、B 剩余、用时；结果用图标 + 文字（check「A 胜」/ x「A 负」），不只靠颜色区分；没有值的格子显示「—」。
- 「怎么算的」说明块（muted 浅灰底）。
- 操作：「在 N vs M 中打开 N vs {M}」、「复制链接」。URL：`be=1`（M 已在 URL 中），打开链接时直接还原结果。

## 边界
- 达到上限：红底提示「200 内无法取胜」+「A 用 200 个{A}仍打不赢 {M} 个{B}。下面是 200 个时的战损。」，只显示 200 这一档。
- N = 1：不显示 N − 1 档，muted 注明「N − 1 = 0，不显示这一档。」
- 改动任一参数后，旧结果标「参数已变，请重新计算」并变灰（不自动重算，避免卡顿）。
