# #603 文明详情 · 概览主栏分区（体验设计 · 2026-11-01）

> 产品信息架构已锁（[#603](https://github.com/linhongcun/aoe2-analyzer/issues/603)）。本稿只定 `#/civ/:en` 概览 Tab 的主栏。不重开范围，不排优先级，不实现。请 Steve 设计通过后再另刀改代码。

玩家打开概览，应能扫出四块：先做什么开局、八项评分、加成清单、优劣和团战位置。现在这四块连在同一栏里，标题、说明、列表和「加粗标签 + 顿号」都是段落，看起来像贴进来的 TXT。信息量不减，游戏数字不改，只改这一栏的分区和节奏。

#602 的页内 Tab 和「相关工具」已在 main（#611）。线框把它们画出来，只为看主栏时菜单还在。本刀的 AC 不覆盖菜单和侧栏。

线框用亚美尼亚 `#/civ/Armenians`。走查图文件名是格鲁吉亚，画面是这一页：侧栏同资料片是格鲁吉亚，八项分和加成都与 `civs.json` 的 Armenians 一致。格鲁吉亚用同一套规则，不另画一张。

## 1. 信息架构

只改概览主栏（`CivDetail` 里 `key: 'ov'` 的 content）。不新开路由。页头、Tab、相关工具、侧栏实体保持已上线的样子。

有 `op` 时，主栏从上到下只按这个顺序：

| 顺序 | 块 | 角色 | 不放什么 |
| --- | --- | --- | --- |
| 1 | **开局建议** | 首要行动 | 三段说明铺满整栏 |
| 2 | **能力评分** | 快扫 | 卡外单独两大段「官方定位」「特色兵种」 |
| 3 | **鲜为人知** | 可选 | 没有条目时的「暂无」和空档 |

`op` 去掉空白后为空，就不渲染开局块，下面四块顺序不变。

数据、科技、更新历史、职业选手视角四个 Tab 的正文不改。数据 Tab 里的八格、雷达和位置盒保持原样，不用概览的芯片替换。

## 2. 视觉层级

方向 C，浅色编辑风。Inter。正文 15px，区块标题 18px / 600，说明不少于 12px。强调色只用 `#a65a14`，而且只出现在 Lucide 占位的浅底（`#a65a141f`）和评分高的两项上（现有 `StatTiles` 的 `is-key`）。图标只用已登记的 Lucide。线框上方块里的字是 Lucide 名，实现换成图标，不把名字留在界面上。

四块内容都用现有 `.detail-section`：白底、1px `#e5e5ea`、圆角 18、`--shadow-1`、块与块之间 24px。不要另做一套卡片皮肤，也不要在开局卡里再套一层描边卡。

可点区域不小于 44×44。数字和「数字+单位」用 `.num`（tabular）和 `.nw`（nowrap），不从中间折开。

### 2.1 开局建议

保留标题「开局建议」。卡里默认只看见三样：

1. **一行路线。** 仍用现在的切分：`op.split('->')`，第一段标「黑暗至封建」，正文含「帝王」标「帝王时代」，其余标「城堡及后续」。每段先走 `civOpeningDisplayText`，再排成一行，时代标签用 muted，段与段之间是「 → 」。这是一段，不是每段一个 `<p>` 或一条 `<li>`。1280 上亚美尼亚是：黑暗至封建 民兵/长矛兵压制 → 城堡及后续 城堡复合弓箭手 + 冠军步兵。显示名以函数结果为准，不要改回 `op` 原文里的「长矛」「复合弓」。
2. **流程行。** `selectOpeningBuilds` 的每条流程占一行：Lucide `chevron-right`、流程中文名（链到 `#/builds?bo={id}&civ={en}`）、需要时的标签。行是浅底 `#f5f5f7`、圆角 10，不是一段字。`kind === 'generic'` 时，标签「通用示意」跟在名字后面，`white-space: nowrap`，不另起「通用流程示意」这段。亚美尼亚只有一条：`18 人口民兵升级武士（Man-at-Arms）速攻转弓手`，其中「18 人口」不折行，链到 `#/builds?bo=maa-archers-18&civ=Armenians`。没有匹配流程时，这一行的位置改成一句现有的「暂无匹配流程。」
3. **次要「查看全部开局」。** 链到 `#/builds`。文字链接，13px，链接蓝，无描边、无琥珀填充，和流程行分开，不抢那一行。可点高度仍 ≥ 44。

原来的三段说明不删，收进卡底的 `<details>`，摘要文字是「路线说明」，前面是 `chevron-right`，默认收起。展开时沿用现有 chevron 旋到向下。展开后按原句，不再加粗成标题：

- 黑暗时代准备经济，封建时代选择开局兵种，再按路线转型。具体分配请查看开局流程。
- 兵种转型是路线参考；下面按资料适用名单列出流程，无明确匹配时标注通用示意。
- 仅 `kind === 'generic'`：暂无资料标注适用的流程，请结合文明加成调整。

「资料标注适用的开局流程」不再单独做成一段标题；对上了的流程就是上面的行。

建议 `data-testid`：卡 `civ-opening`，路线 `civ-opening-summary`，说明 `civ-opening-notes`，全部开局 `civ-opening-all`。流程行沿用现在的链接，不必新 id。

### 2.2 能力评分

一张卡。标题行左边是「能力评分」，右边仍是现有 `RatingLabel`：「主观评分，仅供参考」加 `circle-help`。点开仍是现在的「评分是怎么来的」，文案不改。线框画关闭态。

八格 `StatTiles` 保持 4×2、`aria-label="文明能力评分"`、分母 `/10`、条长按分数。前两名仍由现有排序标 `accent`（亚美尼亚是步兵 9、海军 8），数字和条用 `#a65a14`，其余条用 muted。这不是新口径。

官方定位和特色兵种收进这张卡的脚注，紧贴八格下面，一条 1px 分割线隔开。两行，标签 12px muted、定宽，值 15px：

| 标签 | 亚美尼亚的值 |
| --- | --- |
| 官方定位 | `c.desc`：步兵和海军文明 |
| 特色兵种 | `civDisplayText(c.uu)`：复合弓箭手 (步弓手)，牧师战士 (步兵)（Composite Bowman (Foot Archer), Warrior Priest (Infantry)） |

值可以在卡内换行。不要再在卡外各放一个 `<p><b>…</b>`。

建议 `data-testid`：卡 `civ-ratings`，脚注 `civ-rating-footnote`。

### 2.3 鲜为人知

只在 `civInsights(en)` 有条目时，插在评分卡和文明加成之间，组件仍是 `InsightSlot`（标题「鲜为人知」，列表规则仍按 #584）。亚美尼亚没有条目，线框上评分卡下面直接是文明加成，中间不留空档，也不写「暂无」。

这和 #584 的单位页不同，也和 `InsightSlot` 现在的空态不同：单位页仍固定一块，空时写「暂无」。本刀不改这个组件的空态。文明概览在调用前判断，空则不挂。

有条目时不新写句子。例如马里仍是现在的两条：「蛮王：空城镇中心也能射 8 箭（满驻上限 18）。」「驻扎仍可再加箭。利于前线推进 / TC 对射。」「8 箭」「18」保持 `.num` / `.nw`。

### 2.4 文明加成

独立一块，标题「文明加成」。标题行右侧是现有链接「查看完整加成表」，地址 `#/bonuses`，13px 链接蓝，不放进「相关工具」。

标题下保留现有标签说明，整句，12px muted，只作说明，不当第二条标题：

> 标签说明：已计入表示有可计算的效果，展开可查看适用单位或科技；部分计入表示只有部分工具计入，展开可查看各工具的计入情况；仅文本表示只展示游戏说明。各工具实际支持范围以工具内的提示为准。

下面是清单，不是段落。每行：`chevron-right`、加成原文、右侧标签。行与行之间 1px `#f0f0f2`，行高至少 44（本来就是按钮）。标签不换行，右对齐成一列。展开仍是现有 `BonusBody` 和「查看详情页」，本刀不改展开里的字。线框画收起。

标签仍由 `RowTag` 算：`encoded` 或全部工具计入为「已计入」，有的计入为「部分计入」，都没有为「仅文本」。颜色沿用详情页现在的覆盖：已计入 / 部分计入是 `#1f7a35` 字、`#e6f4ea` 底；仅文本是 muted 字、`#f5f5f7` 底。不要改判定，也不要把线框上的标签写死进代码。亚美尼亚走查当时的结果是：骡车费用、骡车科技效率、团队加成「步兵视野 +2」为已计入，其余三条为仅文本。口径以后变了，跟 `RowTag`，不跟这张线框。

「团队加成」是这块里面的小标题（13px / 600），不是卡外另一段加粗正文。团队行用同一套行和标签。

加成原文不改。行内的 `-25%`、`+40%`、`+2` 用 `.nw` 包住，避免和单位拆开。

建议 `data-testid`：块 `civ-bonuses`。

### 2.5 优劣与位置

独立一块，标题「优劣与位置」。1280 上两列：

- 左列标签「优势」，芯片用 `#1f7a35` 字、`#e6f4ea` 底
- 右列标签「劣势」，芯片用 `#c4281c` 字、`#fdeeec` 底

芯片文案仍是 `strengths(c)` 的前三项和后三项，顺序不变。亚美尼亚是优势「步兵、海军、经济」，劣势「防御、攻城、骑兵」。芯片不是链接，不必做成 44 高的按钮；字号 13px。不要写成 `<p class="g"><b>优势：</b>步兵、海军、经济</p>` 这种整行顿号。

位置在两列下面，单独一行，1px 分割线隔开。文案公式不变：`fl >= pk` 时「边位 Flank」，否则「口袋 Pocket」，括号里仍是「边位 {fl}/10，口袋 {pk}/10」。亚美尼亚是：推荐团战位置　边位 Flank（边位 8/10，口袋 5/10）。「8/10」「5/10」各包一层 `.nw`。

建议 `data-testid`：块 `civ-stance`，优势 `civ-stance-pros`，劣势 `civ-stance-cons`，位置 `civ-position`。

来源行留在四块下面，仍是 `DetailSource`，句子仍是「能力评分为主观近似评分；开局建议请结合文明加成调整」，并链到数据说明。不放进优劣卡。
