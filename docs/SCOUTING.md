# 侦察情报辨析卡（#258）

入口为 `#/scouting`，页面 testid `scouting-page`。这是两组有限的情报辨析资料，不读取游戏、不解析录像，也不猜测敌方真实意图或给出胜率。

## 首版范围与任务

- 常规开局 1v1 Arabia，early 组只用于封建阶段，walled 组只用于城堡阶段。
- early：军事生产建筑已见，但实际军队与后续投入未知。
- walled：墙内外信息不全，经济扩张与侧面部署难区分。
- 每组固定两个并列解释，共四个。核心为相容解释、不能区分的观察、局部补证/反证、缺失信息、下一次补查，以及条件/风险/反例。

确认具体威胁后链接已有快攻应对、城堡前置和混兵情境。它们不是新日志的模板，也不能替未知信息下结论。本模块不建立通用对局日志。

## 事实的限定

固定六项观察，early 使用前三项、walled 使用后三项。每一项各有独立游戏时间、可见区域和陈旧标记，隐藏的另一组输入完整保留以便分享/返回。

状态为未知、这次没有看见、已见到、在限定时刻/可见区域内确认不存在。不存在必须带时刻和明确可见区域，否则暂停解释并保留输入供修正。这个状态永远不能扩成全图或之后一直不存在。

只有未标记陈旧、具有时刻/范围的已见/限定不存在才进入当前局部补证/反证。未见到、未知、已陈旧或缺少限定的信息会列入缺失信息。不会按固定分钟把信息自动判旧；未标记陈旧也不等于网站认证它仍然有效。

补证和需重查线索可以同时出现。醒目标记只提示需重查，具体说明区分限定区域的反证与对“只有经济”等额外排他推断的质疑；界面不删除竞争解释、不自动排除整套计划。新 TC 与前出军队也可同时存在。用户正在考虑的施压/防守/发展只改变提醒，不自动选择路线。

## URL 与恢复

版本 1 的 URL 只含 `sv=1` 与 `data` 两个参数；`data` 为完整 JSON。结构包含 scenario/map/mode/stage/plan/observations，观察对象包含 state/at/area/stale，所有对象键严格匹配。未知、重复或缺失参数、畸形编码、非法枚举/类型、额外字段和超长输入均不能静默恢复。

整个编码链接上限 8000 字符，单个时间串上限 32 字符。时间可为分:秒或时:分:秒；留空为未记录，格式不合法的原文保留可编辑但暂停解释与分享。超过长度或含控制字符、隐藏方向控制、不完整代理项的原文保留在当前输入框，未进入链接，界面明确提示并清除旧手动分享链接，不截断后声称保存。

空首次访问才用默认情境。结构损坏保留原链接、禁用编辑与解释，需用户主动重置；合法但未覆盖的地图/模式/阶段保留条件，显示未覆盖。两种情况不能混用。没有本地存储覆盖链接状态。

## 界面与打印

来源与边界置于折叠区，主要操作为情境/观察选择和并列解释。复制有成功与失败反馈，失败后显示完整可选择文本。打印展示适用条件、当前观察快照、全部解释和来源；隐藏编辑控件，不把输入框的可见高度当全文。深色屏幕打印使用固定白纸/黑字语义色。

## 来源性质

方法来源、实际打开范围、独立交叉核对和八组可复现桌面反例见 [来源审计](design/v0.26.0-audit258.md)。官方与独立教学仅支持持续收集信息/按实见调整的原则；旧数量、时点、配比及绝对预测没有进入本模块。游戏资料口径仍是 DE185872；没有新增游戏数字或声明客户端实测。

需求原帖证明玩家困惑存在，不证明战术正确。YouTube 原视频/评论本轮不可读的限制保留在 [#258](https://github.com/linhongcun/aoe2-analyzer/issues/258) 中。

## 验证

领域专项覆盖全未知、单建筑不足、撤回观察、陈旧/未见、有限不存在、两个解释同时有补证、隐藏组完整往返、无效与范围外差异、时钟格式、严格结构/编码/版本/长度。浏览器专项覆盖实际交互、复制成功/失败、完整分享/刷新、损坏暂停、长时间和短异常字符输入保留/恢复、键盘、深色白纸打印、四宽双主题 AA 和无横溢出/页面错误。

这些验证证明界面与资料条件实现一致，不证明用户判断提升或游戏内战术收益。
