## 必须落地的细节

### 1. URL 错误与正在编辑的坏输入分开

这是现稿正确但容易实现错的地方。新页面不应直接复制旧 Production 的“编辑即重新编码”错误恢复行为。

- 无查询参数进入可加载默认配置；一旦作为分享配置解析，必需参数缺失、重复键、未知版本、未知文明/对象和非法结构进入链接锁定状态，保留原链接，只有明确重置可解除。不要用 `URLSearchParams.get()` 自动忽略重复键。
- 数字字段用原始字符串持有；空串、负数、小数人数、超上限会停算但表单保持可编辑，不自动转默认值。优先采用既有 text + `inputMode` 模式，以免原生 number 控件悄悄清洗粘贴值。字段各自明确允许的数字语法，拒绝非有限数和意外科学计数/十六进制格式。
- 校验“编辑输入不被锁死”和“损坏链接不被洗白”两个独立回归。例如从有效链接清空人数后可重新输入；从重复 `age` 链接点击其他控件不产生有效结果。
- #226 的嵌入生产方案是局部来源状态：内部方案损坏可以显式切换“手动目标”解除该局部状态；若外层商路 URL 本身损坏，切来源不应解除外层锁定。对原始长度与解码后的嵌入方案长度都设有界上限，不反复 URI 解码。
- 文明、时代切换造成对象/科技不适用时，要么明确清除并就近说明，要么保留选择并提示可编辑错误；不得无提示改到另一个单位或默认科技。所有参与计算和来源解释的选择都应进入分享配置。

### 2. #227 以真实施工形态与建造者 workRate 为基线

独立导出应保留最终建筑 ID 与实际施工形态 ID 的对应和字段来源，特别是 TC 的 construction annex 与已建面板 bt 差异。最终建筑面板数字不能直接替代真实施工工期；普通村民任务工作速率也不能漏乘。

- 若独立工具因此与旧 buildSim 不一致，明确显示固定字段来源和差异口径，在新回归中锁定修正后的施工规则；保留受保护 golden，不为让旧结果相同而复制已知漏乘。
- UI 用“理论施工时间”并说明“所有普通村民已同时到场”；人数对照显示人数、完工秒、相对基准提前秒、总村民秒。不能将 `+X% 工作速度` 写成 `−X% 工期`。
- 起始 TC、特殊建造者、尚未确认的文明条件应明确暂停或按已审计条件开放；不能因为其他建筑可算便给该组合套普通村民结果。
- 停采估算的口径要固定为 `施工人数 × 理论施工秒 × 同任务单人采集率`。基准对照另列“相对基准多/少采估算”，不能直接用“提前完工秒”当节省资源；多人可能更早完工但占用更多村民秒。
- 未选采集任务不输出 0 资源损失。选择后用已支持的 gatherModel 资源/科技/距离参数，并明确这些是假设；若不支持所选采集任务，说明不支持，不代入其他任务。食木金石分列，不合成一个资源总价。

### 3. #229 驻留、治疗资格、最大 HP 必须三次独立通过

现稿已明确治疗资格独立，这是正确边界。机械攻城、船、骡车、牧畜、圣物等不能仅因 #224 canEnter/canCreate 就开放治疗秒数；骡车本版保持“机制待核实、暂停”，也不能反称“已证明不能治疗”。

- `created` 只表示已生产后留驻，不给外部受伤单位添加重进入路径；从驻军面板跳转时保留原 entry。混合驻军或不能迁移的科技/数量给一句说明，不暗选任意首行充当用户的单一目标。
- 相关科技集合来自 HP、宿主治疗率、免费/自动前置和合法性，不能沿用仅筛弹丸的科技列表。
- 草药展示百分比与最终倍率，但只在有来源时给数值。若固定数据为增加 500%、最终 6 倍，两个表达同时说明，免费/自动效果各应用一次。
- 阿兹特克僧侣等科技会改变最大 HP。草药前后对照必须明确比较的是同一绝对当前/目标 HP，还是同一缺血量；推荐同一输入并在比较侧超出该侧最大 HP 时显示“此配置下不可比较”。不得静默钳制目标或切换成满血目标。
- 不具资格、零治疗率、待核实分别显示状态与原因；未知秒数为 null/不展示，不显示 0、Infinity、NaN。有效且无需恢复可显示 0 秒和“已达到目标”；非法 HP 先拦截，不能让负数/超最大值因 current≥target 而变成无需恢复。
- 原始浮点值参与计算，仅展示时格式化；例如很小的正秒数不能四舍五入成“0 秒”而误称无需恢复，可用“少于 0.01 秒”等显示规则。模型假设与未实测标记放在结果旁。

### 4. #226 把收入实测与造价假设分开

- “完整周期”旁给直接操作说明：同一交金点连续两次交金之间的游戏秒数；首趟启动和单程不适用。实测值已经含路线、Caravan/文明/队伍影响，不再乘效果。
- 当前数量、目标所需总数、尚需补充数量分开命名。投资显示对应哪一数量（当前/所需/新增），人口同样有对象；不要在用户看到“所需数量”后给无法判断口径的成本。
- 目标为 0 可需 0；单单位收入为 0 且目标为正单列无解，当前总收入仍可展示 0。完整周期依然必须为正，不因目标 0 跳过格式校验。
- 手填实际单价明确是“单车/单船每种资源成本”，零单价允许；显示覆盖状态和来源。切文明/单位时是否继续沿用手填价必须有提示，不能把别的单位实际价伪装成新文明固定价。
- 基础价、常驻已核折扣和未计科技/盟友折扣就近解释，不能把实测收入中已含的科技再次作用于收入，也不能把木金相加叫黄金回本。

### 5. #228 来源去重与研究状态要能解释

- 保留 1–4 玩家槽和全部提供者；同文明来源按稳定来源 ID 去重，不按相同中文文案去重。不同文明同文案仍分别显示，避免丢掉真实来源。
- 团队科技由固定原始团队效果类型与显式复核元数据识别，常驻与研究分区保持现稿。研究条目显示所需时代、地点、前置和未研究/已研究/不可用；晚于当前时代不可用，但不从列表无声消失。
- 若重复文明中仅一个玩家研究了科技，合并卡须仍能说明哪个玩家研究；可以通过“任一提供者已研究”的来源选择实现，不能用一枚无来源全局勾选制造多人同时研究的暗示。若首版按来源整体标记，须明确这个语义并保持 URL 一致。
- 按单位/类别筛选时，已审计关联、确认不适用、未知关联分开；未知不能因为筛选而被当作确定不适用静默丢弃。窄屏用来源卡片/带标签行，不堆四玩家比较横表。
- 不把 viewer 中的选择回写旧模拟器 URL；相关实体链接只做查看详情，不暗示会自动叠加该阵容效果。
