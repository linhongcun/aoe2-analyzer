# 混兵情境卡

`/mixed-army` 是有条件的战术阅读工具。首版只收两组情境、六张固定卡，不做混编胜率、人数、配比或胜负推导。

| 情境               | 支持范围                                                                                            | 固定路线                                                               |
| ------------------ | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 不列颠帝王步弓掩护 | Britons；主力劲弩手492、长弓兵8或精锐长弓兵530；近战骑兵、掷矛手及其组合                            | 长戟守接近路线；轻骑利用空当接触掷矛手；受保护的中型投石车威胁密集目标 |
| 帝王战车与火炮推进 | 自方Turks，对方Bohemians，1v1 Arena；主力火枪手5、苏丹亲兵46或精锐苏丹亲兵557；战车、火炮及长戟护军 | 保护反炮；确认空当后的翼骑侧切；改换位置与资源                         |

纯战车只作诊断对照，不新增完整纯兵种攻略。额外僧侣、其他攻城或其他组合明示暂未覆盖；选择其他文明、模式或主力不自动替换，也不表示没有应对方法。敌军观测形态不成为本方可训练资格。

每卡列解决的威胁、主力/掩护/攻城职责、条件、代价、失效反例、备选、下一观察和有日期的来源。仅克制单独主兵种的方案不能直接外推受保护阵容。侧路未知不算空当；资源自报不算系统验证。

## 前置记录的语义

遵循 [v0.25.0前置工程审阅](design/v0.25.0-readiness-review.md)。`completedForms` 是用户明确确认该具体形态所需升级实际完成，包含其所需前置升级；免费获得也要本人确认。选择单位不会写入确认。`completedUnlockTechIds` 独立记录化学47、火炮术10等本页审计研究；`completedBuildings` 独立记录当前可用的生产建筑。

`mixedUnitPrerequisites` 复用固定目录、树格、`productionBuildings` 的反事实潜在资格及既有形态索引。反事实科技集只用于判断文明、时代和地点，不写入实际确认；`effectiveProductionTechs` 的自动前置与免费项不是玩家已研究证明。形态候选升级科技不全部AND。僧侣等地点来自eco/production，不用目录 `Unit.b` 单值推断。

区分文明不可用、时代未到、缺形态/研究/建筑、暂未支持及所列前置满足。同一记录确认高形态完成却仍选低形态时，保留选择并提示已被升级取代。特殊未核对或单位池外的形态返回unsupported。只有所列前置及观察条件均满足的路线进入条件满足区；这不认证人口、兵力、持续资源或战斗结果。

必要研究和原研究建筑现存分开处理：科技已经完成不要求原研究建筑仍存在；新增单位的生产地点则需确认。过时、未来时代或错误文明的完成记录保留为可修正冲突，不静默删除。

## 分享与边界

URL用`mv=1`和`build=185872`，保存情境、文明、时代、模式、主力、实际敌军及形态、地形/目标阵型、侧路/撤路、保护位置、食物/木金持续能力和三组完成确认。无参数首次访问默认关键观察未知且无完成确认。不使用本地存储盖过链接。

严格拒绝缺键、重复键、未知键、版本不匹配、非法编码/枚举/数字格式、重复数组和超过6000字符的链接。结构损坏锁定，保留原链接，显式重置才能编辑；安全可恢复的未知实体或时代越界保留原字段、暂停推导并允许修正。不得截断分享。复制失败显示可手动选择的完整链接。

来源在手工内容`src/content/mixed-army.json`逐项记录：Steam2022/2024需求讨论、2023军队运用指南、2024 Arena指南、2023火炮术讨论及官方185872补丁。已实际打开核对；论坛意见有争议，不用其绝对输赢或旧数值。具体游戏数值仍由固定DE185872生成数据提供，尚未完成该版本客户端混编交战实测。PK和生产页只作局部资料链接。

页面输入在资料和来源之前；四宽360/375/390/1280、浅深主题、键盘、44px目标、AA与无溢出由专项浏览器用例验证。软件检查与客户端游戏实测分别陈述。
