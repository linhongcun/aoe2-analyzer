# 圣物收入（Issue 238）

`/relic-income` 估算已存放且生效的固定圣物数量，在固定游戏时长内的黄金、食物、木材与石料。四种资源分别计算，不相加、不换算等效村民。版本数据为 DE185872；本工具没有运行该版本游戏客户端验证逐帧结算。

## 数据与复现

```bash
python3 scripts/relic_income_build.py
python3 scripts/relic_income_build.py --check
python3 -m unittest discover -s tests/py -p 'test_relic_income238.py' -v
npx vitest run tests/unit/relicIncome238.test.ts
```

导出器只发布派生数值至 `src/data/relic_income.json`。`.dat` 和解析缓存留在已忽略的 `scripts/.cache/`，不提交。原始游戏文件由 `dat_source.fetch_dat()` 校验固定 SHA256；缓存键同时包含该 SHA 与完整探针内容。`--check` 逐字比对重新构建的派生结果，变化时失败，不悄悄更新。

原始数字来源：`SiegeEngineers/auto-mods@0c38027504532826c9922e4db77e2c1d33554291` 的 `dat/empires2_x2_p1.dat`，SHA256 `4aa2f0a719e88e5f1502517eddb27c669aeb40c2fe9d8c4f3eec7751c01e7baa`，解析器 `genieutils-py==0.1.2`。固定完整审计见 [v0.25.0-audit238.md](design/v0.25.0-audit238.md)。

引擎字段语义单独记录于 `meta.fieldSemantics`：

- [UGC Guide resources.md @ 3dab81b6（2026-10-10）](https://github.com/Divy1211/AoE2DE_UGC_Guide/blob/3dab81b6e8d4e416b8b44eb0b7cb928ef561ae0d/docs/general/resources/resources.md)：资源7为持有圣物数；191/225/264/265为黄金/食物/木材/石料的每分钟速率。
- [AGE Lists.cpp @ 0bd1b417（2025-12-15）](https://github.com/Tapsa/AGE/blob/0bd1b417ca6d77aa0b8a2e84a37f2d5f178944de/AGE_Frame/Lists.cpp)：Type1资源设/增、Type6资源乘、Type26敌方资源乘、Type36中立资源乘、任务151 Generate Resources。

语义资料核对日为2026-10-20。其历史示例数字不用于参数；例如语义文档勃艮第旧例30食物，与本次固定 `.dat` 的效果783数值20不同，采用后者。

**计算直接使用 `.dat` 原始 Float32 数值，不先保留六位小数。** `modifiers.*.value` 与原命令的 `D` 相等；`displayValue` 仅用于倍率文案。阿兹特克原值 `1.3300000429153442`、大干道原值 `1.100000023841858`。页面只对展示结果格式化，逐项展示数的相加可能有末位差异；内部贡献与结果按未舍入值对账。不据此宣称还原客户端每一轮浮点运算或资源显示舍入。

## 参数字段与支持范围

63个 `.dat` 文明模板的相关初始资源一致，本站56个常规文明全部映射成功。`civs[cid].resources` 中191为30，225/264/265为0。整个 `.dat` 的单位任务、header任务中没有引用这些收入资源的任务：普通圣物285仅在Gaia模板存在，任务为空；修道院104也没有151收入任务。收益是引擎资源规则，不能从 `bird.work_rate=1` 推断每秒收入，也不能将修道院工作速度加成套进来。

全局相关资源命令严格限定为下表7条；新增命令、收入任务、文明基础分歧、异常值或不符合已审计条件的操作使导出失败，须重新审计。

令 `N` 为数量、`T` 为游戏分钟，`A` 和 `H` 分别取原始阿兹特克与大干道倍率或1，`E` 为单来源无神论0.5或无时1，`F` 为勃艮第20或0。则黄金速率 `N × 30 × A × H × E`，食物速率 `N × F × E`，木石0；各资源总量分别乘 `T`。

默认无神论选项明确是「未生效」假设。多个来源、状态未知、期间研究或外交变化时，黄金、食物与黄金覆盖/缺口为 `null`，页面显示未核实并暂停；木石的已核零结果保留为部分结果。没有用团队来源去重推断多个无神论的实际执行次数。

来源台账按通用、阿兹特克、勃艮第、本方大干道、单来源无神论顺序保存每一步差值，跨来源交互计入后执行的一步。重复文明队友具有不同槽位，提供者全部保留，但同文明团队来源只执行一次。本方来源自动参与同一去重。

## 立陶宛与亚美尼亚

立陶宛699–702号自动科技以资源7的1/2/3/4件为门槛；699前置104与107，之后逐级依赖前一科技，效果736–739相同。每级 Type4/C9/D1025，编码为近战攻击类别4增加1。只展示骑士38、重装骑士283、游侠569、烈堤司1234和精锐烈堤司1236的适用说明与最高+4；超过4件不继续叠加，不修改PK或科技模拟器。翼骑兵不在命令目标中。原效果还有1813萨瓦尔，但普通立陶宛科技树不可用，仅保留在审计信息中。

亚美尼亚949/effect951在修道院条件107后生成辅助建筑1118，辅助建筑触发957/effect952，短暂设置资源283=1生成存放的285，再复位。104等修道院形式通过effect941替换为1806强化教堂。该链不改变每件收益；用户已经输入的免费圣物不会再自动加一件。格鲁吉亚强化教堂同样不额外提高每件收入。

## 输入、零值与分享契约

- 数量为非负整数；时长、目标金耗为非负十进制有限数；每项0–1000000，文本最多32字符。该上限是工具输入限制，不宣称游戏存在这一圣物数量上限。空值、负值、指数、NaN/Infinity、超限不回退默认。
- 0数量的速率及期间总量均0。0时长仅期间总量0，非零数量每分钟速率仍正常。目标金耗0不除零，覆盖额 `min(目标, 黄金速率)`，缺口 `max(目标−黄金速率,0)`。
- 最多三名队友，位置固定为a1/a2/a3；允许同文明玩家，效果按文明来源去重。留空表示本方案未提供该来源，不自动猜测真实阵容。
- URL版本1包含文明、数量、分钟、目标、三个队友槽位、大干道与无神论状态。严格检查重复/未知/缺失键、编码、版本和布尔格式；长度上限8000字符，不截断。
- 结构错误展示原完整链接、锁定条件、暂停结果，需显式重置。可修正的数字/文明/枚举语义错误保留原输入并允许直接改正。
- 分享清除无关外层查询，保留部署项目base，完整方案放在 `#/relic-income?...`。结构或输入无效时禁止复制，未核实但结构有效的状态可以分享其暂停状态。剪贴板失败显示可选择的完整链接。
- 数据异步加载失败时暂停并提供重试，不使用普通文明默认数据代替。

不模拟获取/携带/途中增减、研究完成时刻、战役奖励、自制场景或玩法模组，也不认证资源人口足以持续生产整支军队。

## 模块接口与验证边界

页面：`features/relicIncome/RelicIncome.tsx` 默认导出，根testid `relic-income-page`。领域入口：`newRelicIncomeConfig`、`validateRelicIncomeConfig`、`calculateRelicIncome(config, data)`、`decodeRelicIncome`、`encodeRelicIncome`、`relicIncomeShareUrl`。生成数据有独立 `validRelicIncomeData` 保护；结果用 `valid/paused/invalid` 和逐资源可空值区分状态。

专项单元测试覆盖固定组合、原始浮点、零语义、提供者去重、来源变化、黄金缺口、暂停、阈值、非法输入、完整分享和项目base。Python测试覆盖参数来源、全局路径、任务反查、阈值链、亚美尼亚数量来源及未知路径/异常值拒绝。浏览器专项由整合执行者挂接正式路由后执行，包含四宽双主题、键盘/44px、无溢出、分享成功失败、严格恢复、未核实和数据加载失败；这些是工程验证，不是客户端游戏实测。
