## 实际核对的迁移契约

### Production → 商路供给 → 原 Production

- `src/features/production/Production.tsx` 只在链接错误与领域错误均为空时显示带入入口，错误状态不生成可继续使用的链接。
- `tradeIncomeProductionHref` 经 `tradeIncomeFromProduction` 将完整原生产配置编码到 source，保留文明、时代、科技、采集距离和全部需求行；没有把页面四舍五入后的金耗当成唯一来源。
- 商路端 `decodeTradeProduction` 先做独立完整/严格校验，再用现有 `calculateProduction` 求未舍入黄金 spend。贸易测量编辑只影响供给，不重写来源生产方案。
- “查看原生产方案”按原 config 重新编码，能够恢复原需求/科技/距离；手动目标切换是显式操作。原生产来源损坏不会因编辑交金或周期被清除；外层坏 URL 仍由独立解析错误锁定。
- 有效黑暗时代生产方案可能带入一个尚不能训练贸易单位的贸易时代状态；这是页面可编辑的合法性提示，不会改写嵌入生产方案的时代，未发现错误回退默认生产配置的路径。

### 建筑模拟器 → 多人施工 / 驻军回血

- `BuildingSimulator` 传入当前建筑 ID、显示中的文明和时代、当前科技选择集合；没有从页面面板 bt 反推施工数值。
- 施工 `constructionLink` 填全版本化 URL，保留同文明/时代合法科技，不把不合法科技硬塞进新分享。独立领域保留真实施工形态、建造 workRate 与已建面板差异口径；不修改旧 buildSim 或 protected golden。
- 库曼封建攻城器厂的 minAge 由既有 `getGarrisonBuildingAge` 及施工独立 minAge 特例保持为2；链接不会强制退回城堡时代。
- 回血入口只对已有宿主目录开放，`healingLink` 独立筛相关 HP/治疗/驻留解锁科技，并由领域合法性作最终检查；建筑比较文明 cmp 只是原面板比较，不会被误当成当前文明带入。
- 免费/自动草药由独立模型处理，不因原建筑面板没有441复选项而漏掉，也不为携带字段而人为重复加入。
- 概览页“比较多人施工”是无模拟上下文的基础入口：按建筑首个可用文明与建筑时代初始化；带当前文明/时代/科技的入口位于模拟器，两者文案有区分。

### 单行驻军 / 混合驻军 → 回血

- `GeneralGarrisonPreview` 仅在当前驻军无解析/领域错误时生成回血迁移链接；超容量/非法驻留等错误不会生成绕过校验的迁移入口。
- 只有一行单位种类时，传入该单位 ID 和原 entry，helper 不把 `created` 偷换成 `enter`；领域最终检查该单位是否确实能以该方式驻留。单行数量不作为回血目标数，这是独立单个受伤目标的预览。
- 多行或空列表不暗选其中首行来声称继承全部军队，使用 fresh 合法对象；入口写明“查看单目标回血，进入后选择对象”，相邻说明写明不迁移混合数量、只保留有意义的文明/时代/单位/科技。
- helper 的 fresh 分支从合法可进入/自产留驻候选中选择，重新筛候选相关科技，并用目标 HP 模型初始化；没有让外部受伤僧侣借生产留驻变成可重新进入的路径。
- 特殊对象仍保持原独立状态：圣物 deposit 不虚构受伤治疗、零率宿主可进入查看零率状态、机械/骡车待核实不因共享入口而自动放开。
- 源页面未被改写；新工具用常规 Link 进入，因此浏览器返回可以恢复原混合 army 与原单位种类。

### 文明对比 / 加成列表 / 全站导航

- Compare 以当前 A/B 文明顺序创建两名玩家，可保留重复文明；团队科技仍默认未研究。新 viewer 不修改旧 Compare、PK、建筑和经济模拟器计算模型。
- 加成列表添加独立队伍汇总入口，原实体详情链接与列表路由保留。
- 四个新路由是新增 exact 页面；既有建筑、生产、市场、经济收益、加成详情和旧重定向未删除或重写。
- 新工具加入 SECONDARY_TOOLS/ALL，供搜索和面包屑识别；首页附四个明确入口，原六个主工具卡片顺序保持。共享 entry 采用局部样式与令牌，44px最小高度、窄屏可换行，不引入全局正文样式变化。
