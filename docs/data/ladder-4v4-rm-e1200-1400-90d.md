## 原样写入的字段

每个文明：`en`、`winRate`、`playRate`（来源字段 `pickRate`）、`games`、`wins`、`ci95Low` / `ci95High`（来源字段 `wilsonLow` / `wilsonHigh`）。数字记号与来源 JSON 一致，没有四舍五入。56 个英文名都在 `src/data/civs.json`。`wins / games × 100` 与 `winRate` 的差在 1e-14 以内。出场率之和为 100。

`brackets[0].games` 是各文明 `games` 之和 **867358**。这个和除以 8 余 6，所以它是评分带里的玩家出场次数，不是完整对局数。来源没有另给对局总数，这里不补。

## 没有走势

来源每个文明另有 `trend`：按自然月，多数从 `2023-09` 到 `2026-10`，局数远大于本窗口的 `games`。那不是近 90 天里的序列，所以快照不写 `trend`。丹麦、撒克逊、瓦兰吉只在 `2026-09` 与 `2026-10` 有月点，且两点局数之和等于本窗口 `games`（文明本身更晚才出现）；这两点仍是自然月，不是已核对的窗口内序列，同样不写。

表上的走势列应走空态「无走势」。schema 仍允许以后在同一文明上加可选 `trend`（`period`、`winRate`，可选 `games`），且必须是这一窗口内的点。
