## 发布衔接与线上核对

main 的完整 CI 约需四十分钟，而脚本默认只等线上页脚 600 秒。应先完成 main CI/Deploy，再启动 Release。Actions 的 `GITHUB_TOKEN` 首次推 main 后通常不会触发另一条 CI，不能依赖该方式启动网站部署。

本次将正式 Release 接续在同仓库 main 的 push CI/Deploy 成功之后，保留手动恢复；准备阶段只读验证可信事件、版本和祖先关系，之后才运行有写权限的发布步骤。已正式发布的同版本幂等跳过，tag 指向不符仍拒绝。

本机 `gh` 的 401 和网站目标的网络策略拒绝，与 GitHub 连接器、git transport 或正式 runner 的能力是不同问题。保持凭据及网络策略，使用已授权且适用的连接器和正式 runner 完成操作及真实线上验证，不把本地替身站点当成线上。

复制功能要点击实际按钮，再用实际生成的地址重开，保留项目部署前缀和参数；从静态入口改选后，要读取 Router 的新查询。完整 Compare 专项自建本地服务器并读取 dist，线上专项须独立使用真实站点，不能只改 BASE_URL 就宣称验证了生产环境。
