# #559 地图边路 / 中路推荐 · 交互规格（Jony · 体验设计 · 2026-10-31）

> 产品已锁定（Steve / hongcun，#559，2026-11-01，P1）。本稿只定这一刀的界面。不重开范围，不排优先级，不把 1v1 天梯写成团队站位。

地图详情增加两列编辑推荐：边路、中路。有稿的列每条是文明链加一句理由。没有稿就写待补。默认口径是开图 4v4。

不做：用天梯胜率排团队位置、#558 团队协同、实时 API、地图生成器、窄屏精修。文明页已有的「边位 / 口袋」评分条不动。

## 1. 放在哪

**留着现在的「推荐文明」，新区块放在它下面。**

那张列表回答「这张图的开局练谁」。它挂在开局链接下，只有阿拉伯半岛、竞技场、游牧、岛屿，每张两条，链到 `#/civ/…`。边路 / 中路回答另一件事：开图 4v4 坐哪一边。合成一个标题，会把开局建议和团队站位读成同一份名单；换成两列，后三张图已核对的跳转会变成待补。

| 项 | 规格 |
| --- | --- |
| 位置 | 详情文章内，开局参考（含开局链接、岛屿码头段、推荐文明）之下，「来源与核对日期」之上 |
| 没有 guide 的地图 | 同样画出这一块。黑森林今天没有「推荐文明」，不能因此藏起两列 |
| 不放 | 地图选择器、页头、首页、`#/ladder` |

地图名仍是现有 `h3`。其下「地图特点」「开局参考」「推荐文明」仍是 `h4`。

两列标题用 `h3`：「边路推荐」「中路推荐」。字号 18 / 600，英文辅标 12px muted：`Flank` / `Pocket`。它们和地图名同级，不收进「推荐文明」那个 `h4`，避免大纲把团队站位读成开局的子项。从 `h4` 回到 `h3` 是故意的。

文明页和团战计划继续说「边位 / 口袋」。本切片用锁定文案「边路 / 中路」，不顺手改旧词。

## 2. 两列

PC（视口 ≥ 900px）两列等宽，间隙 24px。左 / 上是边路，右 / 下是中路。只有一列有稿时，另一列仍占住自己的位置。

窄于 900px：取消网格，两节上下排，顺序不变。不横滑。不为本切片做 360 精修。

列内不显示条数。3 条和 8 条用同一行样式，不另做「更多」。

## 3. 一行

用行，不用 chip。Chip 装不下这一句理由（设计规范 §5.7）。

整行是一个链接，`href="#/civ/<英文名>"`，与现在的 `Link to={/civ/${id}}` 相同。可访问名就是行内文字。最小高度 44px。悬停底 `#f5f5f7`。焦点环 accent 2px、offset 2px。

| 块 | 规格 |
| --- | --- |
| 图标 | 现有 `CivIcon`，这一列里收成 28px。不改全站 56px 的默认尺寸。`alt=""`，名字在旁边 |
| 名字 | 中文名链接色 `#0066cc`、600；英文名 muted、12px、字重 400。英文不换行 |
| 理由 | 一句，13px、muted `#636366`。PC 上跟在名字右侧；窄屏换到名字下一行。不截断，不省略号 |

同一文明可以两列都出现，各写自己的一句。不另做「两边都适合」角标。

有稿的列不放反馈链接。

## 4. 模式与免责声明

两列上方一条，全页只出现一次。有稿、缺一列、两列都空，都画。

| 控件 | 规格 |
| --- | --- |
| 模式 | `<span class="pill">`，不是按钮。文案「适用：开图 4v4」，「开图 4v4」加 `.nw`。底 `#f5f5f7`，字 muted 12px。无 accent 描边 |
| 免责声明 | 「编辑口径，非官方推荐」。muted 12px，Lucide `info`。不进每一行，不用警告色，不用红 |
| testid | `map-pos-mode`、`map-pos-disclaimer`；整块 `map-positions` |

本切片不提供模式切换。封闭图、水图没有稿时，仍是这一枚 pill 加两列待补，不改成「适用：封闭图」之类的句子。

## 5. 待补

某一列的数组缺失或长度为 0：这一列是虚线盒，不是空白，也不是「暂无推荐文明」这种会像结论的句子。

| 项 | 规格 |
| --- | --- |
| 容器 | 虚线 `#c7c7cc`，底 `#f5f5f7`，圆角 12，字 muted。不用 `--color-bad`，不用红 |
| 图标 | Lucide `inbox`（`Icon.tsx` 已登记），muted |
| 文案 | 边路：「边路推荐待补」。中路：「中路推荐待补」。只此一句 |
| 反馈 | 现有 `FeedbackLink`，`kind="data"`，`label="反馈数据缺口"`。图标 `message-square-warning`。盒内链接单独 ≥ 44px，颜色 `#0066cc`。新标签打开预填 issue |
| 语义 | `role="status"`。testid `map-pos-empty` |

两列都空：两只盒子，各一条反馈。有稿的列不放盒子。不因为邻列为空就藏起有稿的那一列。

## 6. 数据

编辑稿，不进生成的 `mapCatalog.json`。放在 `src/features/maps/positions.ts`，键是地图 id。

```ts
type MapPosTip = { civ: string; reason: string };
// civ = civs.json 的 en
type MapPositions = {
  mode: 'open-4v4';
  flank: MapPosTip[];
  pocket: MapPosTip[];
};
```

| 规则 | 说明 |
| --- | --- |
| 有稿 | 该数组长度 3–8。不足 3 或超过 8 时，界面不补人、不删人；内容检查报出，页面仍照稿渲染 |
| 待补 | 缺这张图，或该数组长度为 0 |
| 理由 | 一句。不写胜率、样本、Elo、分段 |
| 禁止来源 | `#/ladder`、aoestats、文明页全局 `fl` / `pk`。那些分不随地图变，拿来排序等于给每张图编同一份名单 |

首批至少阿拉伯半岛两列都写满。其余地图可以没有键。线框里的文明和理由只定密度和语气：边路偏弓、中路偏骑，可以重叠。实现时另写编辑稿，不把线框样例抄进去，也不要按 1v1 排名去填。

## 7. 窄屏

视口小于 900px：边路一节，中路一节。理由在名字下，行仍 ≥ 44px。「开图 4v4」不折行。不横滑。不要求 360 / 375 精修；390 能读、能点即可。
