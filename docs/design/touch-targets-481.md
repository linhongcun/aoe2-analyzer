# 术语与页脚链接热区（#481）

依据：[issue #481](https://github.com/linhongcun/aoe2-analyzer/issues/481) 与本轮[冻结范围](grok-feedback-2026-10-28.md)。现有 390px 浏览器实测：开局「查看术语与缩写」约 91×16，页脚数据链接约 228×24，资料来源链接也只有 24px 高。

## 范围与可验收行为

- 仅补开局列表的「查看术语与缩写」及页脚实际不足的链接热区，使边框盒宽、高均至少 44px；短链接（如 Lucide）也满足宽度要求。
- 页脚数据版本、资料来源及许可链接保持原文字与目标地址。现有反馈链接热区和来源折叠控件保持；来源展开后所有链接同样可触达。
- 使用局部 class／现有页脚选择器，沿用设计令牌、字号及焦点可见样式，不放大整站普通内联链接，也不重排导航或新增文案。可用内边距扩热区，但不得让相邻链接热区互相覆盖、挡住其它操作。
- 360／375／390／1280、明暗主题下自然换行，无横向溢出、控制台错误或页面异常。对齐与行距以保留清晰阅读、链接容易点击为验收标准，不要求保持旧的不足行盒高度。
- 市集所谓「20×20 无名图标按钮」经核验是「已研究行会」复选框。它已有隐式关联标签，实测标签 324×44，可访问名称正确，所有真正按钮均有名称且热区足够。本项不改市集、复选框或其命名，不添加重复 `aria-label`。

## 验证

`tests/e2e/touchTargets481.spec.ts` 覆盖四宽与明暗主题：市集复选框保留可访问名称及至少44×44标签热区，标签可切换勾选；开局术语、页脚数据版本与展开后的来源链接均至少44×44，点击中心真实命中各自链接，目标地址保留，页面无溢出或报错，并保存截图。既有反馈入口另由原反馈回归验证保持。先在未改产品的基线执行，确认因实际不足链接而失败。

2026-10-28 在与 `d2c7f91` 相同的原产品、4392开发服务、系统 Chromium 上执行 `390 light`：市集命名、44px标签、标签点击切换和按钮名称断言通过，随后术语链接高度断言期望至少44、实际16，1项真实失败。首次准备运行因测试自身的嵌套标签定位器写法超时，修正相对定位器后才取得上述有效产品失败；两次原日志均保留，未将定位器失败当作产品证据。页脚与完整四宽断言尚未到达，产品未修改。

最终产品提交 `92b9f05c784d9dc6c1e4dd8e5c304e7901c8d53b`／tree `f8ced559ba343180c12853795bf059fbeec6b29a` 的实际构建成功（950份静态页），4392 preview与系统 Chromium上的本项四宽明暗8项、原反馈热区12项、页脚元信息5项及开局入口2项共27项通过（35.7秒），16张实际截图保存。实际主题属性、点击中心命中、链接边框盒与市集复选框回归均核实。局部ESLint、CSS语法和颜色检查通过，生成文件无源码漂移。

实施前检查既有回归发现：桌面反馈入口需保留紧凑高度，390px元信息三项需顶边对齐。因此按原规格保留 `.fblink`，只补本轮数据／来源链接，元信息文本与链接共享44px行盒维持对齐；新用例相应限定至本轮目标，44×44断言未放宽。原反馈用例及其期望未改，并实际通过；不把这项实现者检查写作独立复核。
