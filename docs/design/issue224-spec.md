# #224：所有建筑与混合驻军预览

版本 v0.22.0，固定数据 DE185872。维护者明确将 #218 扩展为所有可驻军建筑，并选择同时支持各类可驻军单位。本文是实现规格与工程证据，不冒充他人签字。

## 入口与范围

建筑详情的「驻军预览」页签由生成的轻量潜在建筑清单决定；不能只读通用面板容量，也不能继续固定四个建筑。清单包含文明/时代开启的形态、训练后留驻和特殊驻留。真正没有任何驻留机制的建筑不显示页签。

建筑科技模拟器提供「查看驻军配置与弹丸预览」，带入文明、时代和已选相关科技；泛用筛选必须来自新数据，不能再维护手写十项科技 ID。

主动回驻、训练后留驻、存放圣物分别表达。军队候选属于所选文明和时代，兼容性同时看建筑类型掩码、单位分类覆写、实际驻军任务、训练位置或特殊存放规则。包含资料站单位、通用村民/牧畜、可驻留的骡车及弑君模式国王。没有逐一加入战役英雄或任意地图编辑器对象。

射击建筑显示理论弹丸，非射击建筑正常展示驻留容量；治疗量、牧畜经济收益、圣物黄金、盟友/招降单位各自科技、实际伤害、DPS与胜负不计算。

## 布局

使用相邻建筑页的编辑风及 `garrison.css` 设计令牌。所有文字至少 12px、交互触区至少 44px、数字与单位不拆行，无新颜色字面量或符号图标。

| 宽度 | 配置                 | 驻军清单                                   | 结果                                           |
| ---- | -------------------- | ------------------------------------------ | ---------------------------------------------- |
| 360  | 文明整行、时代下一行 | 每组单位整行；进入方式、数量和移除自然换行 | 容量三块；射击数字三块，标签可换行、数字不换行 |
| 375  | 同 360               | 同 360，容器 `min-width:0`                 | 同 360                                         |
| 390  | 同 360               | 同 360，长中英文选项不撑开页面             | 同 360                                         |
| 1280 | 文明与时代两列       | 单位、进入方式、数量、移除四列             | 三列数字及两列补充事实                         |

背景使用 `--color-surface-2`，边界 `--color-border`，强调 `--color-accent-soft`，错误 `--color-bad-soft`/`--color-bad`，正文与辅助文字 `--color-text`/`--color-muted`。复用 `--fs-sm`、`--fs-num-xl` 和 `--space-*`。原生输入、select、details与按钮支持键盘操作。

## 页面内容与状态

页头标题「驻军配置与弹丸预览」，说明主动进入、生产留驻和圣物存放，并提供复制方案。文明改变后清空自选科技和军队；时代改变后清空军队并保留仍适用的科技。时代选择使用领域层的实际最低时代，包含库曼封建攻城武器厂。

清单每组包含单位、数量和进入方式。进入方式只显示该单位允许的选项；训练后留驻明确说明离开后未必可重新进入，圣物存放不把携带它的僧侣也计为驻留单位。每组可以移除，空清单是有效空驻军。增加组数有固定上限，重复配置按领域层确定规则处理，不漏算数量。

结果顺序：

1. 容量、已占用、剩余槽位。人口消耗不冒充驻军槽位。
2. 射击建筑显示基础、驻军追加、总弹丸及上限；箭矢和炮弹用正确单位。容量上限不等于弹丸上限。
3. 每组兼容原因和贡献状态；单一单位可查看阈值和满容量结果，混合配置按合计贡献统一取整，不能逐组先取整相加。
4. 科技选择与免费、前置联动。折叠说明保留原始数据版本、机制来源与理论范围。

状态要求：

- 加载：等 core/trees 与惰性数据就绪，不闪现通用结果。
- 正常：数量和槽位可编辑、完整方案可复制。
- 空驻军：仍显示基础弹丸和实际容量，不能把所有空建筑都称为不开火。
- 非射击建筑：明确「不发射弹丸」，仍显示驻留兼容和容量。
- 文明/时代未开启：明确当前不可驻军，保留文明/时代编辑，不伪造容量。
- 不兼容/超容量/未知科技：错误可见，停止伪有效射击结果；有效输入可以修改。
- 来源未核实：具体贡献与依赖它的弹丸结果使用空值和具体说明，容量可继续核对，不以 0 冒充结论。
- 链接语法损坏：保留原查询、停用常规编辑及复制，只允许显式重置。
- Clipboard 拒绝：提供可手动复制的完整只读链接；状态变化后清除旧成功提示。

## 分享和兼容

新格式为 `gv=2`、`army=单位ID:数量:e或c或d,...`，保留 `civ`、`age`、`gtechs`。进入方式编码由领域层集中解析，UI不自行拼接。重复关键参数、非法 ID、ID 整数溢出、过多行以及新旧参数混用均拒绝。格式完整的记录保留原始数量字符串：删空、负数、小数、非数字或溢出数量由语义校验停算，仍可直接改正。UI避免把不同记录改成同一单位和方式，导入的重复记录则保留并要求显式重置。

原 `garrison=N`/`gtechs` 链接无新格式时按村民 83 迁移，保留原参数语义。旧数据、领域API和49项领域回归保留；#218 中「城堡不显示入口」的旧首版断言与新范围冲突，改为验证新入口，不改原数字和错误状态期望。通用模型中新发现的机制差异必须单独说明和验证，不为迎合旧实现而设置建筑特例。不修改 `tests/**/v0*-acceptance*`。

## 数据与领域

新增独立 `garrison_general.json`、生成脚本和通用纯函数，不手改生成数据。导出完整建筑/单位基础、文明自动/免费/条件科技、时代形态、主副弹丸、驻军类型与任务。原始 .dat、缓存和genie环境不提交。

数据矩阵和来源说明随实现提交，固定数据与软件回归不声称是客户端实测。有关多弹丸、副箭、充能或特殊分类的来源冲突必须记录，不能静默套用旧 AoC 规则。
