# #215 市场买卖预算规格

用户已在本次会话明确要求将 #214–218 全部逐个开发、测试与部署。本文是执行规格，不冒充 Steve 或 Kent 的审查签字。

## 页面与行为

- 路由 `#/market`，在经济子工具集合与快捷搜索登记，持续生产页提供明显入口，不扩展首页主工具卡数量，标题「市场买卖预算」。桌面内容最大宽 1160px。
- 两份独立方案 A/B，分别保存文明、已研究行会/大干道、四种资源初始库存、三种手续费前基价、有序买卖操作。默认示范「卖 200 石料，再买 100 食物」。
- 编辑按钮切换当前方案；可将当前完整方案复制到另一份再修改。对照区始终分别列出四资源净变化、花费与所得黄金，不把异类资源相加成损耗或评分。
- 基价高级区默认折叠，明确「黄金 / 每 100 资源，未含手续费」，不能填面板买/卖价。报价只做输出。
- 每项操作输入方向、资源、笔数，可增加、删除、上下移。每笔 100 资源；最多 20 项、总共 10000 笔，避免恶意链接冻结浏览器。
- 预算不足时停止在该项的具体一笔，标所需、现有、缺口，只保留已经成交的前缀。无交易时库存不变。库存/基价/数量无效时暂停该方案计算。
- 逐笔明细含资源和黄金收支、成交后库存、该资源下一笔双向报价与基价，每页 25 笔。A/B 方案分享链接恢复全部输入与顺序。剪贴板失败时提供可选中的只读链接。
- 不计建造、科技研究成本、资源采集、其他玩家交易。科技复选框仅表示该科技已经研究。

## 状态与布局

360 / 375 / 390：卡片 padding 16px；初始库存两列，交易编辑一列，每项内方向/资源/笔数三列，操作按钮单独一行；对照与报价单列；明细转带字段名的卡片。1280：卡片 padding 24px、库存四列、交易两列、对照两列、报价三列、逐笔明细表格。浅深主题均使用现有 `--color-*` 令牌；正文继承 16px、标签与明细 14px、最小辅助文字 12px，所有控件与 summary 点击高度至少 44px；数值及数值单位禁止换行。

覆盖默认示范、无操作、预算不足、非法输入、恶意/版本不兼容分享链接、未开放科技置灰、操作与笔数上限、剪贴板失败、明细分页。数据本地打包，无外部加载状态。

## 数据审计与适用性

费率从 `scripts/data_sources.json` 固定 `.dat` 导出，SHA256 `4aa2f0a719e88e5f1502517eddb27c669aeb40c2fe9d8c4f3eec7751c01e7baa`。新增独立 `scripts/market_build.py`，不改变通用解析器缓存、不改 PK 阵亡交换比 `trade.ts`。文明资源 78 为默认交易费率；效果 tech15、355、506 分别为行会、萨拉森、大干道。行会可用文明从固定 techs.json 读取；萨拉森和印度斯坦均无行会，因此不做猜测叠加。

市场交易动作没有出现在 `.dat` 的 Market unit_header 任务内。起价、步进、边界及取整是引擎规则，独立登记 `scripts/market_rules.json`，不能称作从 `.dat` 导出的数值。

已实际打开核验的依据：

1. [官方 Preview 125283](https://www.ageofempires.com/news/age-of-empires-ii-definitive-edition-update-preview-125283/)：食物起价从 100 改 115，初始标准买价 150、卖价 81；木材/石料起价未变。
2. [官方 Update 66692](https://www.ageofempires.com/news/age-of-empires-ii-definitive-edition-update-66692/)：非萨拉森文明研究行会后最低买价由 25 重设 23；萨拉森最低买价由 25 重设 21。与基价 20 乘费率一致，不加旧的 25 黄金下限。
3. [市场百科](<https://ageofempires.fandom.com/wiki/Market_(Age_of_Empires_II)>) Exchange 段提供 100 单位、2 步进、20–9999 边界；Changelog 描述行会最低买价 25，与官方更正冲突，因此不采纳；Trivia 的旧触顶交易数量对应 3 步进，内部有历史混杂，还指出显示价与实际交易可能存在取整差。
4. [2022 玩家记录](https://www.reddit.com/r/aoe2/comments/wqvj3x/market_changes_you_may_have_missed/)交叉支持从 3 步进恢复 2，但不是同版引擎证据，不能把帖子数字当固定游戏数据。

因此首屏始终明确「预算估算；引擎取整未同版实测」。本工具实现逐笔整数报价的预算模型；游戏内部可能保留小数余额，因此累计黄金和预算不足临界点可能与模型不同。所有库存不足判定也仅是本模型口径。不得声称已经与 DE 185872 引擎完整逐笔对账。没有安装该版游戏及可重放成交记录，无法诚实完成原 issue 的「同版引擎实测」数据门槛；此项验收仍需真实引擎证据。模型实现与软件测试不能替代该证据。

## 验证

纯函数单测覆盖独立基价/手续费、逐笔取整与批量等价、交易顺序、预算不足前缀、边界、大量交易、无操作、输入错误、文明科技可用性、分享恢复与坏链接。Python 测试覆盖导出来源与文明身份断言。Playwright 覆盖库存编辑、方案复制/切换、顺序、失败提示、分享与四宽浅深主题溢出、报错和截图。所有模型数值测试明确属于模型回归，不伪装成游戏实测。
