# 产品运营交接

给接手本站日常使用和玩家反馈的人。职责以 [CONTRIBUTING「角色」](../CONTRIBUTING.md#角色) 为准：运营回答信息能否找到、操作是否顺畅、结果能否看懂，并写明具体场景和卡点。Issue 阶段和交接按 [CONTRIBUTING「Issue 生命周期」](../CONTRIBUTING.md#issue-lifecycle)；同一正文持续记录，不另开评审/实施 Issue。本文只记录已经用过的问法和口径。范围、设计和开发验收仍看 CONTRIBUTING、[TESTING](../docs/TESTING.md) 与 [AGENTS「开发执行」](../AGENTS.md#dev-exec-2026-11-10)。

站点目前主要由维护者自己使用。PC（约 1280）上的路径要走通，窄屏保持能读、能点。旧布局、旧入口和旧链接可以按该页的核心任务改掉。观察用来提改进，不是上线门禁，也不进入 CI 或全尺寸矩阵。玩法入口见 [`src/features/gameGuide/`](../src/features/gameGuide/)、[`src/features/mixedArmy/`](../src/features/mixedArmy/) 和 [内容购买目录来源](../docs/DATA-UPDATE.md#content-catalog)，本文不写攻略。

## 谁处理什么

运营在 `阶段:需求提出` 收集玩家反馈和功能建议，在同一 Issue 正文记录可复核场景、实际卡点、观察/复现证据和未核实项，再交产品评审。需求范围和优先级由产品（Steve）定；运营不替产品作决定、不排期、不另开后续阶段 Issue，也不做每个 PR 的全站验收。其余阶段和同一正文模板见 [Issue 生命周期](../CONTRIBUTING.md#issue-lifecycle)。

## 从实际问题走一遍

先有一局里的问题，再沿玩家会走的页面查和算。例如：印度斯坦使用翼骑兵、火枪手和少量手推炮，若改换一批帝王骆驼兵，黄金差多少。

比较之前先分开口径：

- 目录上的基础值，以及选定文明、时代和科技之后的有效值。
- 一名单位的训练价，一项科技的一次研发费，一次转型的总投入。
- 固定数量的训练总价，以及持续生产里按每分钟计算的消耗。
- 单兵模型给出的结果，以及混编时要另外看的交战。

下结论前确认这些单位在该文明、该时代可训练，并记下页脚三行：站点版本（`vX.Y.Z`）、数据版本、构建。三者各记各的，站点版本不能代替构建。正式结论用页脚上的数据包；公开测试服（PUP）不混进去。某批历史资料的分法见 [HISTORY-DATA](../docs/HISTORY-DATA.md)，只约束该批。

本站不够用时，再查当次能打开的官方补丁或资料。查不到就标待核，不凭记忆补数。

计算结果用来辅助判断，不预设“前排肉盾+远程输出核心”。主力输出可以由近战单位承担；先按文明、对手/地图、交战窗口和已有兵力判断阵容与职责。

多兵种转型核算时：

- 先核对已完成科技和文明免费科技，只计算新增投入；共用科技只研究一次，独立路线分别核算。
- 再核对各兵类共享与独立的铁匠铺攻防科技、兵种线升级、特色科技和生产建筑；将剩余研究时间、待建建筑及扩产时间纳入成型判断。

协同、机动、攻城器是否被保护、阵容何时成型、补兵资源和经济是否接得上，都要结合局面判断。已有静态反制时，仍要看具体窗口能不能用。造价高的强单位，接着问怎样成型。对局感觉只作为问题来源。没有当次记录时，不写自己打过或看过录像。

## 两个改进入口

### 波斯步弓手：目录价看不出省金

波斯步弓手（卡曼达兰）让弓兵训练免金，改为多耗木材。旧的单位 PK 仍显示目录价 25 木、45 金，省下的黄金要手算。提出的场景是：已经选择该科技时，PK 给出有效训练价，并写明哪些效果已计入、哪些未计入。产品核实后，这项显示进入 PK（[#943](https://github.com/linhongcun/aoe2-analyzer/issues/943)）。DE 188329 当次核到满科技波斯弩兵为 50 木、0 金。一次研究费用另计，不摊进每名训练价。

要补上的是目录价和有效训练价之间的断层。核对之前保持为待核现象，不为波斯单独写公式。

### 印度斯坦：混编要的是训练总价

需要同一文明、同一时代的多行单位：每行数量、有效单价、小计，以及食物、木材、黄金合计，合计不含研究费。当时持续生产按每分钟消耗计算，固定军队总价只能逐个详情手加。设计通过后，持续生产增加了训练总价（`#/production?mode=train-total`，[#978](https://github.com/linhongcun/aoe2-analyzer/issues/978)）。火枪手和手推炮能否训练受化学控制，研究费不进总价；原始规格见[基线原件](https://github.com/linhongcun/aoe2-analyzer/blob/362f1ed7a7acebbecb08f43dfa04684828eba923/docs/design/issue204-production-spec.md)。

当次有效训练价：20 翼骑兵 + 20 火枪手 + 2 手推炮 = 2500 食、450 木、1450 金。把 20 翼骑兵换成 20 帝王骆驼兵后为 2000 食、450 木、2650 金，差额为多 1200 金、少 500 食。差额只比训练资源，不含战力、研究、升级和已有兵力。换数据版本后重算。

## 反馈怎么写

先查已有 issue。功能建议用 [功能建议模板](../.github/ISSUE_TEMPLATE/feature_request.md)，游戏事实用 [数据错误模板](../.github/ISSUE_TEMPLATE/data_error.md) 并附来源。疑似缺陷写下复现、截图和页脚三行，用 [问题报告模板](../.github/ISSUE_TEMPLATE/bug_report.md) 交给测试；运营不宣判是否成立。页脚链接会带上页面和数据版本，场景仍要自己写全。只记录真实出现的需求。

一条反馈写上：实际目标与场景；当次站点版本、数据版本、构建和完整 URL；做了什么、页面上找到什么；卡点以及对判断的影响；希望得到的结果（写明总价还是每分钟、含不含研究费）；截图或资料出处；已知边界。

模板末尾的实现者清单若与现行 TESTING 不一致，以 CONTRIBUTING 和 TESTING 为准。

## 单据状态

历史上曾把流程写成需求、设计、产品评审后另建实施 Issue；训练总价案例中，设计通过后没有实施 Issue，当时开放 Issue 为零而需求未交付。这是历史交接缺口的记录，不是现行流程。现在由同一 Issue 正文按五个阶段继续更新，具体规范见 [CONTRIBUTING「Issue 生命周期」](../CONTRIBUTING.md#issue-lifecycle)；本段旧状态词不作为阶段标签。

[CONTRIBUTING「Issue 生命周期」](../CONTRIBUTING.md#issue-lifecycle) 是现行统一规范：产品决定、实现授权、体验规格、完成态设计图和交接都留在同一 Issue 正文；每次实际 UX 交付都须将可直接查看的设计图嵌入正文。只有纯 docs/data 且无 UI 时可由产品记录 UX 不适用及理由。转入软件开发前仍须有该事项明确的维护者授权证据。

2026-11-13 曾有「设计通过后可直接开实施 issue、不必再问」的建议，用来避免有稿无单；现行同一 Issue 生命周期已取代另开实施单的做法。阶段标签或设计通过都不授权开发，进入软件开发前仍须有维护者明确记录的实现授权。双路暂停和设计索引里的短时回复是历史记录，不作为运营步骤，也不扩大开发授权或排路线图。

## 文明笔记

同一文明的新经验补进同一份笔记。写错的删除或标成撤回，数据版本过了就标过时。三条分开：机制事实（附本站数据版本或当次打开的来源）、使用者认可过的经验、尚未核对的推断。别人认可可行，只记成认可，不记成自己用过。

越南笔记曾把象兵主要写成太贵，漏了高生命前排可以让后排持续输出。火矛兵加帝王掷矛手的想法，在被指出容易被受保护的攻城器压制之后撤回。留下的是失效条件，不用一条反制否定相关单位。

### 土耳其：火枪、翼骑与少量火炮

- **机制来源**：当次打开的 [AoE2Insights 土耳其科技树](https://www.aoe2insights.com/civilization/turks/tech-tree/) 和 [土耳其加成与科技树](https://www.aoe2counterhub.com/civs/turks.html) 列出免费化学、火药单位生命值与训练速度加成及翼骑兵线免费升级；普通火枪手列为帝王时代射箭场单位。网页未标游戏数据版本，给当前机制或精确数值结论前应复核；本文不固定数值。
- **用户认可的经验**：以普通火枪手作输出核心，保护火枪手和火炮；由可补充的翼骑兵承担前排消耗，并在有接近机会时清除敌方攻城器，少量火炮提供攻城与反攻城支援，可作为常见帝王后期组合。这是土耳其特定情境下的经验，不是所有阵容的固定模板。不是个人对局记录，也不是模拟胜率。
- **适用边界**：火枪手和翼骑兵都消耗食物；已有射箭场时，普通火枪手便于从射箭场扩产。无骑射兵基础时，不要仅因资源分工较好就默认从零转重装骑射；这一路线要投入升级和相关科技，已有骑射兵时比较会不同。阵容选择还要看现有兵力、成型时机、转型投入、生产建筑及扩产能力、补兵资源和对手/地图；不能仅凭资源互补判断优劣。
- **名称注**：本站将 [Hussar（#441）](https://linhongcun.github.io/aoe2-analyzer/#/unit/441) 称为“翼骑兵”，勿与 [Winged Hussar（#1707）](https://linhongcun.github.io/aoe2-analyzer/#/unit/1707)“波兰翼骑兵”混淆。

### 马来：双手剑士、长戟与少量手推炮

- **机制来源**：当次查看的 [AoE2Insights 马来科技树](https://www.aoe2insights.com/civilization/malay/tech-tree/) 与 [AoE Buddy 简体中文马来科技树](https://aoebuddy.com/zh-hans/tech-tree/malay) 列出劲弩手、双手剑士、长戟兵、手推炮和攻城技师。民兵系免金特色科技（Forced Levy）将民兵系黄金成本换为额外食物，但科技本身仍耗食物和黄金；研究后双手剑士耗食物，长戟兵耗食物与木材，劲弩手和手推炮耗木材与黄金。马来步兵护甲升级免费。外部页面未标游戏数据版本，本文不固定数值。
- **用户认可的经验**：偏省金的帝王中后期，以免金特色科技后的双手剑士持续补兵作近战主输出；按骑兵压力补长戟兵反骑，少量手推炮拆防御、反攻城。劲弩按敌军或已有弩手基础选配。此为用户认可经验，不是模拟胜率或通用必胜方案。
- **投入与边界**：双手剑士和长戟兵都由兵营生产，共用步兵攻击科技；马来步兵护甲免费，但两条兵种线升级独立，免金特色科技仍需另行研究。手推炮需要攻城武器厂，攻城技师是可另行投入的强化科技；劲弩需靶场与兵种线升级，射手攻防科技按需求追加。结合已有/免费科技核算新增投入，避免重复计费。人口、食物与木材供给、剩余研究时间、建筑扩产和补兵距离限制持续补兵；步兵需接近展开，敌方范围伤害可能限制堆量，双手剑士也不应无条件当作耐打肉盾。
