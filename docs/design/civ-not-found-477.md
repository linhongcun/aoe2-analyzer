# 未知文明地址空态（#477）

依据：[issue #477](https://github.com/linhongcun/aoe2-analyzer/issues/477) 与本轮[冻结范围](grok-feedback-2026-10-28.md)。基线 `d2c7f91` 的 `CivDetail` 将未知 ID 静默显示为文明列表，用户无法判断链接是否有效。

## 范围与可验收行为

- 未知 `/civ/:en` 显示独立空态，一级标题为「没找到这个文明」，说明可检查拼写或通过搜索查找；保留并显示用户输入的 ID。
- 提供「查看文明列表」（`/civs`）、「回首页」（`/`）和「打开全局搜索」三个入口。搜索复用现有全局搜索行为，Esc 可以关闭；不新增搜索算法或对输入自动纠错。
- 短 ID、中文及长连续字符均可读，长 ID 在自身区域换行，不撑宽页面。容器使用现有 `.pane`、标题、说明与按钮样式，颜色使用现有设计令牌，正文至少 12px，动作热区至少 44×44。
- 合法文明（如 `Tatars`）继续显示原详情；`/civs` 列表、详情数据加载、已有面包屑和其他实体路由保持原行为。未知 ID 不写入最后查看文明，不假扮合法文明或静默跳转。
- 不增加常见拼写映射、别名跳转、其他实体空态或新的公共导航条目。

## 验证

`tests/e2e/civNotFound477.spec.ts` 在 360／375／390／1280、明暗主题下核对未知与长 ID 空态、三个入口、合法文明及列表回归。检查无横向溢出、无控制台错误或页面异常，并保存短／长 ID 截图。先在产品未修改的基线上执行用例并记录真实失败，再实施。

2026-10-28 在原产品 `d2c7f91`、独立4392开发服务、系统 Chromium 上执行 `390 light`：1项真实失败，原因是未知 `Tartars` 页面缺少「没找到这个文明」标题，旧页面仍显示文明列表。产品尚未修改，长ID与恢复操作的后续断言未到达，不声称已通过。

实施后的四宽明暗8项通过，保存16张短／长ID截图，并核实实际主题属性、三入口和合法文明。首轮6通过、2失败是新用例误量了main内已有桌面反馈入口的27.8px热区，随后仅把定位范围收紧为空态及其3个恢复入口，44×44断言保持；原日志保留，未改共享反馈入口。验收使用父提交 `da5a1d4` 加本次477工作区源码的开发服务，启动时构建标识仍为该父提交；不将其标记为最终部署产物。
