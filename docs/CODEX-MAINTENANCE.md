## 1. 产品主题（是什么 / 不是什么）

**是什么**：帝国时代 II 决定版（AoE2 DE）的**中文资料站 + 计算工具**——文明/单位/科技/建筑百科、科技树与加成，以及对比、对局助手、模拟器、单位 PK、开局、市场预算等可分享的计算页。线上：https://linhongcun.github.io/aoe2-analyzer/。界面文字全部简体中文。数据版本以页脚与 `scripts/data_sources.json` 为准。

**不是什么**：

- **不编造游戏数值。** 数字只从生成数据与固定 `.dat` 派生结果读；记忆、旧帖、猜测一律不算。issue / 设计稿 / 测试与数据冲突时，以数据为准并在 issue 说明。
- **不做无关大功能。** 不做实时读盘、账号系统、自动推荐最优策略、改游戏平衡、爬站批量抓内容、自建天梯后端等偏离「资料 + 计算」主题的扩展，除非维护者在 issue 里明确授权并写入范围。
- **不做未授权的批量集成。** 一个 issue 一个实现 PR，按批准顺序串行；不得伪造他人审阅结论。是否合并、发布按维护者已记录的授权执行，不能把持续发布授权解释成自动领取所有 issue。

## 2. 工作节奏

1. **一次只认领 1 个 issue**（一个执行者、一个 PR）。
2. **同时在审的 PR ≤ 2**（含别人的）。审阅位满时只准备草稿，不新开 PR。
3. 当前 PR **合完再拿下一个**；不要并行囤积分支等合。
4. 开 PR 前先查该 issue 是否已有 open PR，有则跳过。
5. 普通已授权更新默认一个 issue、一个 PR 直接对最新 main；仅需要多项冻结集成时使用 `release/vX.Y.Z` 并更新到其最新提交。

## 3. 门禁（对齐 CONTRIBUTING）

维护者已授权采用**实现者之外的独立代理复核＋按风险选择的 CI**作为现行默认，不再以指定人员签字为前置条件：

- 执行者准备实现、规格、失败用例和验证证据；独立代理核对验收标准、改动范围、代码、测试与数据来源，界面改动同时核对设计规格及四宽。
- 在 PR 中记录**实际验证的提交 SHA、复核范围、结果和未解决问题**。不得由实现者代写独立复核结果，存在未解决问题时不得宣称通过；需要产品决定的交维护者明确授权。
- CI 按功能影响生成 maintenance/civ-ui/targeted/full 计划，每份代码做一次必要验证。小 UI 不运行未变计算、数据再生成或无关整站回归；release/main 仅在同仓库真实成功来源、代码树、策略和覆盖范围匹配时复用证据。缺证据执行当前必要计划，不为阶段名称额外重跑全量，详见 [TESTING](TESTING.md)。
- 只改文档或只改样式（不动逻辑和测试）的 PR：CI 绿即可采用轻量审阅规则。轻量审阅仍须通过对应范围的 CI，不要求额外整站全量。
- **不得伪造他人结论、删除分支、修改仓库权限或放宽测试。** 没有合并/发布授权时不执行相应动作；本项目已记录的授权范围内，完成适用门禁后按顺序集成并发布。
- **Relates 与 Fixes：** 网站实现 PR 使用 `Relates #N`，完成实际部署、线上核对和正式 Release 后直接关闭 issue。`Fixes #N` 合入默认分支即关闭，只用于合入即完成的工程或文档范围。#571 曾按旧流程在 tip `4b6d35a6` 关闭，作为历史保留，不再构成具名人员的关闭门槛；代码门禁仍是实现者之外的独立代理复核。
- rebase 后若 `git range-diff` 证明自身改动不变，可沿用相应独立复核并记录新旧 SHA。当前 CI 仍核实实际代码树、策略与范围；不足时补当前必要验证，不无条件冒用旧 run，也不机械重复相同验收。

**默认 CI（#749）**只跑 static、build 和一条不可复用的 Chromium 窄冒烟；main 聚合成功后才上传 `deployed-site` 并部署。不要把四片、24 路由、axe、单测或 data 加回默认。手动 full 才并行 static-main、unit、data 与四片浏览器。最终 `test` 核对本次计划内的阶段和精确 case；失败、取消、超时、缺片、错构建均阻断 deploy。#338 留在 full。见 [ci-749](design/ci-749.md)。

仅 v2 原始阶段执行证明可复用，v1 无效。GitHub 核实同仓库成功来源 run/attempt/数字 job/artifact，并匹配实际 tree、策略、工具链和精确检查/文件/case 集合；不沿用任意继承链。缺失或坏证明补跑所缺必要阶段。build 与默认 browser-1 不复用；main 重新构建真实 SHA 并执行窄冒烟，而不是每次 24 路由。static-main 只在手动 full。不能把复用写成本次重新执行。

CI/Deploy 与 Release 各自从 GitHub `run.created_at` 起共享30分钟预算，包含初始/阶段/部署排队、同 run 重跑、命令和网络等待。不能按阶段重置预算；诊断最多另用90秒且不能变绿。平台进程清理存在延迟，不承诺物理30:00瞬间停止。Release 校验准确 main 外部 v2 gate 和已部署产物字节，不重建。独立完成事件时序报告记录 wall、排队、全部 runner 分钟和最慢片，PR→main→deploy→Release 整链另列；10分钟只是实测目标。

提交前可预估已提交 Git 范围（先 `git fetch origin main`；不含工作区修改）：

```bash
node --input-type=module <<'NODE'
import { execFileSync } from 'node:child_process';
import { planRange, selectCiPlan } from './scripts/ci-scope.mjs';
const git = (...args) => execFileSync('git', args, { encoding: 'utf8' }).trim();
const head = git('rev-parse', 'HEAD');
const base = git('merge-base', 'origin/main', head);
const plan = selectCiPlan(planRange(base, head), { GITHUB_EVENT_NAME: 'pull_request' });
console.log(JSON.stringify(plan, null, 2));
NODE
```

实际 Actions 的精确检查与 case 集合见 plan artifact 和 `Freeze exact selections and verified phase reuse` 日志。单测 `unit_chromium` 只决定 unit 阶段是否需要安装浏览器；build 冷烟测及浏览器 worker 独立安装，统一通过剩余预算执行镜像修复和 `npx playwright install --with-deps chromium`。
