# #757 竞技场不挖金直城的黄金收支

核对日 2026-11-07。只说明穆伊斯卡、埃塞俄比亚、瓦兰吉人在标准资源下、不安排村民挖金时，点城堡前的黄金够不够。不是已实测开局，不写人口和时间，不保证食物、建筑或地图资源一定够。

## 固定数据包

固定数据包是 `SiegeEngineers/auto-mods@e293dc106b0f3b0ceac2db98409fbcc5c921190b` 的 `dat/empires2_x2_p1.dat`，SHA256 `d0aefd92428e2215d6f4d9b1d544901e6f171e19183f9e0b88218de5153a337f`。本次用 genieutils-py 0.1.2 读了这份文件，并与 `src/data/eco.json` 对过。站点展示读 eco.json，不把 .dat 提交进仓库。

两个日期不是同一件事：

- 官方公告署期是 2026-10-27。2026-11-07 打开 [Update 188329](https://www.ageofempires.com/news/age-of-empires-ii-definitive-edition-update-188329/)，页面写 Age DE Team October 27, 2026。本站 `src/data/patches/188329.json` 的 `releaseDate` 与 `sourcePublishedAt`（`2026-10-27T10:04:41-07:00`）也是这一天。
- 数据版本字符串 `DE Update 188329 (2026-10-28)` 来自 `scripts/data_sources.json` 的 `patch.date`，写进 `eco.json` 的 `meta.patch`。它是本站数据包记录，不是官方发布日期。[#486](update-188329-486.md) 另把北京时间公开日期记为 2026-10-28，与发行日 2026-10-27 不混写。

## 标准开局黄金：AC 未满足

本站开局模型使用食物 200、木材 200、黄金 100、石料 200。页面把它标成「本站模型假设，当前 DE 待核验」。依赖这 100 黄金的差额都写成「若开局黄金按模型为 100」。这不勾掉 #757 里「起始黄金须有当前 DE 独立交叉核验」的强制验收。

2026-11-07 用同一份 188329 `.dat` 看过不列颠、穆伊斯卡、埃塞俄比亚、瓦兰吉人的文明资源向量：资源 0–3 和 91–94 都是 0。这里的 0 是「这条向量没有再加减起始资源」，不是玩家库存为 0。库存由随机地图和大厅的资源设置另外覆盖，不在这条向量里。本次没有找到带版本、设置和出处、能单独证明「标准随机地图、标准资源、黑暗开局是 100 黄金」的当前 DE 来源。官方升时代说明没有印出开局库存。社区帖里的资源档数字互相不一致，也不能当作 188329 的证据。

低资源、高资源和特殊开局不在本说明里。

## 穆伊斯卡

科技 1367，效果 1367：对科技 101、102、103 的黄金费用乘 0.5（Type 101，资源 3，模式 2）。没有食物、木材或石料命令。玩家文字是「进入下一个时代所需黄金成本 -50%」。

城堡点击黄金因此是通用 200 乘 0.5 后的 100，食物仍是 800。页面把 800 食物加 200 黄金标成通用基准，避免和折扣后的 100 混成同一笔。若开局黄金按模型为 100，不织布差额是 0；先付织布 50 之后还差 50。这两句差额仍取决于未核验的开局黄金。封建升级本身不花黄金。

## 埃塞俄比亚

| 科技 | 前置     | 研究地点  | 效果                 |
| ---- | -------- | --------- | -------------------- |
| 587  | 只有 101 | -1 / 0 秒 | 食物 +100，黄金 +100 |
| 588  | 只有 102 | -1 / 0 秒 | 食物 +100，黄金 +100 |
| 589  | 只有 103 | -1 / 0 秒 | 食物 +100，黄金 +100 |
| 871  | 只有 298 | -1 / 0 秒 | 同一条效果 613       |

科技 298 的名字是 Feudal Age start，效果名是 Disable age2 on advance bonuses，会禁用科技 587。它不是正常研究封建（那是科技 101）。标准黑暗开局不研究 298，所以不发 871；587 在封建研究完成时入账，可以用来点城堡。588 要等城堡研究完成，不能回头支付点击城堡的费用。

官方更新 66692 写过：起始时代不是黑暗时代时，才对起始时代补发升级时代奖励。这和上面的分工一致。

若开局黄金按模型为 100，加上封建到账的 100，点城堡前的差额是 0。先织布则还差 50。这两句同样取决于未核验的开局黄金。封建到账本身和「城堡到账不能支付点击」不依赖那 100。

## 独立待核：模拟器与科技 871

这是实现时看到的差异，产品复核没有独立复现。本 PR 不改模拟器，也不另开单。

- 条件：标准黑暗开局，不是封建时代开局。科技 871 的前置只有 298；298 的效果会禁用 587。
- 证据：188329 `.dat` 中科技 871 名为 `C-Bonus, +100f, +100g GS`，`requires` 只有 298；科技 298 名为 `Feudal Age start`，效果名为 `Disable age2 on advance bonuses`，Type 102 禁用 587。
- 模拟器：`src/domain/buildSim.ts` 把黑暗时代、资源 0–3、且没有对应 91–94 条目的发放算进开局库存，没有先看 871 的前置是不是 298。`tests/unit/buildSim.test.ts` 因此期望埃塞俄比亚第一步黄金比通用开局多 100。
- 状态：待独立复现。本说明的文明页按数据包排除 871，不把模拟器的第一步库存当成标准黑暗开局。

## 瓦兰吉人

科技 1475 设资源 33 为 34，并把资源 298 设为 10.010000228881836。资源 33 用来调用效果函数。玩家文字和 [官方介绍](https://www.ageofempires.com/news/varangians-civilization-deep-dive/)（Age DE Team，2026-09-04）都只写牧羊、捕鱼和狩猎也会产生黄金，没有写百分比。

既有 UGC 资源表把 298 说成主采集收入的额外黄金百分比，并要求 EffectFunction34。这份 .dat 里没有该函数体。本说明因此不把 10.01、10% 或由此反推的 1000／1500 食物写成结论。竞技场只谈牧羊和狩猎；捕鱼不是这张地图的默认资源，浆果、农田和其他食物也不算进这条产金。

若开局黄金按模型为 100，不织布时点城堡前还要产生至少 100 黄金；先织布则至少 150。这两句取决于未核验的开局黄金。不保证羊和猎物一定够。比例和采集量的待确认不变。
