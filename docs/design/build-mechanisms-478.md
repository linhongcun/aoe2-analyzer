# #478 开局机制注册与行为守恒

本次只整理开局模拟内部扩展点和来源证据维护方式，不新增文明支持，不修改生成的游戏数据、数值、页面、文案或既有验收期望。基线为 main `08ad03b0335f9b98a3b893694b793674c1f21b3b`。

## 模块与扩展方式

- `buildSim.ts` 保留时间推进、付费队列、建造、研究和资源记账；原公开入口继续由该文件导出。
- `buildSimMechanisms.ts` 的 `CIV_MECHANISMS` 按文明登记上下文工厂、开局动作转换、农田模型、研究/建筑前置、施工工期、时代应用例外和模型说明。未登记文明使用既有通用路径；游戏倍率继续从实际 `eco` 输入读取。
- 同文件 `APPLICATION_RULES` 以具名 `RowApplication` 字段登记效果来源和所属文明。原葡萄牙、蜀效果按完整行来源识别、无需同名文明的行为保留。时间线和独立采集率工具各自保留原子校验策略。
- `buildSimEffects.ts` 负责通用数值修正和 `RESOURCE_APPLICATIONS` 资源通道。已知通道的新文明主要增加注册项及对应来源配置；全新物理机制增加一个小的类型化 hook，不在时间循环追加文明分支。
- `buildSimCivRules.ts` 保留既有完整来源、对象类别、重复行和成对效果校验；来源身份常量不替代游戏倍率。
- `buildSimCoverage.ts` 保留效果分类、支持范围与理由，资源语义通过 `RESOURCE_HANDLERS` 登记。新来源需同时具备应用规则和覆盖分类，不能只让一个效果绕过整行校验。
- `buildSimNotes.ts` 用附注注册表按原有顺序输出文明说明，通用来源说明保持跨文明识别。

新增文明沿用现有机制时，先添加来源身份/校验与生成数据，再在上述注册表填写适用项，并补行为与损坏来源用例。来源不足或未知效果必须继续拒绝应用；注册表不是放开未知来源的白名单。已有复杂的魏/孟加拉出生、亚美尼亚研究增强、格鲁吉亚免费起始车继续调用各自经过审阅的领域模块。

## 必须保持的合同

1. 同输入的完整时间线（数值、误差带、异常、付费时刻、附注顺序及可选字段）与基线一致，包括不支持文明的旧取整语义。
2. 时间线对每条效果行实行原子校验；`gatherRate` 仍仅对原来的鞑靼、玛雅、西西里、斯拉夫、高棉实行整行原子门，其它文明的特殊兼产通道单独检查原子性。不得统一两者而改变损坏来源输入的既有结果。
3. 分类顺序保持高棉、斯拉夫、亚美尼亚、格鲁吉亚、魏、孟加拉及后续通用规则；跨文明移置的已知标记仍拒绝。
4. 玛雅完整配对与重复团队行门控、魏/孟加拉奖励行对象身份、空的免费村民事件字段均保留。
5. 亚美尼亚增强仅在实际研究完成时应用；格鲁吉亚起始车仍为零时刻完成实体；法兰克免费研究去重只作用于原有文明。
6. `simScope` 保持默认缺省上下文及转换后开局实体集合。附注里蜀、马里、瓦兰吉、鞑靼、玛雅仍用无文明 scope，西西里使用文明 scope。

## 验收与验证

执行者之外的代理在实施前核对上述范围和合同。实现后由独立代理复核具体提交，并对基线与候选执行全 56 文明加通用文明、八个开局及团队/住房/来源损坏变体的完整输出对照；对全部采集任务在零、近、远距离检查采集率、携带量和额外收入。既有 `#197` 单测和浏览器回归保持原期望，不重录快照、不放宽断言。

新的永久回归测试覆盖输入不变、跨文明来源、原子门差异和破损来源拒绝。源证据维护工具和摘要格式见同 PR 的来源维护文档；历史证据字节不因本次重构删除。
