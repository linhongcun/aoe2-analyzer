# #224 驻军领域模型与计算口径

数据来自固定 DE Update 185872 的 `garrison_general.json`；生成、形态别名去重和字段出处见 [数据说明](../data/garrison-general224.md)。本功能没有运行同版本游戏客户端；下列弹丸结果是有来源的理论模型，不能当作客户端实测。

## 入驻与容量

模型分别校验文明、时代、建筑容量、单位类型位和单位的入驻任务。显式 `sizeClass` 优先于旧对象类别；例如牧师战士按宗教单位处理，传教士按骑乘单位处理。`trait` 的容器标记不作为普通占员的必需条件。

三种入驻通道保持分开：

- `enter`：单位具有匹配任务，建筑允许该类型从外部进入。
- `created`：当前建筑可生产该单位，包含无外部入驻权限的生产后留驻。科技新增生产地点按原始训练位置指令处理；兵营生产近卫军需要无政府状态，马厩生产答剌罕需要掠夺者。
- `deposit`：仅用于圣物存放，以持圣物僧侣的特殊任务校验；不把持圣物的僧侣另算成第二个占员，也不计算圣物资源收入。

每个占员占一个容量位；不使用人口消耗或碰撞体积推测占位。驻军总数先统一校验再计算弹丸，不能将多个兵种各自的箭数取整后相加。非射击建筑正常显示容量和兼容性，弹丸数为 0。

依据：[UGC 属性 30、54、163](https://ugc.aoe2.rocks/general/attributes/attributes/)、[官方 Update 169123](https://www.ageofempires.com/news/age-of-empires-ii-definitive-edition-update-169123/)，以及固定 `.dat` 的 `bird.tasks`、建筑类型位、时代形态和生产地点。旧任务头对一些新单位不完整，因此以现代单位任务读取结果为准。

## 单位驻军火力

令 `A` 为单位最终穿刺攻击、`R` 为原始攻击间隔、`F` 为最终驻军火力系数：

- `F = 0`：贡献为 0，不能按倍率 1 处理。
- `F < 0`：`A / R + abs(F)`；穿刺攻击为 0 时直接使用固定项，因此渔船的零攻击间隔不会造成除零。
- `F > 0`，普通单弹丸：`F * A / R`。
- `F > 0`，有单独副弹丸的普通齐射：`F * (A + 0.8 * 副弹丸数 * 副弹丸最终穿刺攻击) / R`。

正系数乘数与负系数加固定项的含义来自[官方 2025 更新预告的 Garrison Fire Power 章节](https://www.ageofempires.com/news/a-sneak-peek-at-new-content-coming-to-age-of-empires-ii-definitive-edition/)。副弹丸经验式来自 [DE Infosheet，Extra arrows through garrisoned units](https://steamcommunity.com/sharedfiles/filedetails/?id=2169547705&l=german)，该页将公式署名给 T-West。官方 [Update 50292](https://www.ageofempires.com/news/aoe2de-update-50292/) 确认修复了多弹丸单位的驻军贡献，但没有公开其数字公式。

将 2021 年副弹丸经验式与后来开放的 `F` 乘数组合，是本工具的模型推断。固定版本诸葛弩、钦察本体系数约为 0.9；副箭经验权重 0.8 是独立的模型系数，不把两者视为同一字段。含多箭占员的结果必须显示“多弹丸驻军按公开公式估算，未完成 DE 185872 客户端对账”。弹丸自身系数为 0.8 只能作为数据线索，不能单凭该数值宣称引擎读取该字段。

充能类型 6、7 按普通未充能齐射的 `total` 估算，不把临时 `max` 当作普通齐射数量；界面明确显示此状态限制。战车 1962 的普通多弹丸形式没有单独副弹丸字段，当前缺少明确其回退算法的独立来源，因此保留合法入驻和容量，弹丸贡献返回未知，并显示“当前多弹丸形式尚未建模”，不误称数据缺失。

## 建筑与弹丸

有副弹丸的建筑，分母使用最终副弹丸穿刺攻击除以建筑攻击间隔；否则使用建筑自身攻击。该区别来自 DE Infosheet 的建筑弹丸说明。选择防御箭塔或大型箭塔形态时，也应用已完成形态升级对副弹丸 505 的效果，而不只登记科技 ID。

令 `P` 为原始基础弹丸槽数、`M` 为原始上限、`D` 为上述建筑单弹丸火力，先计算 `min(M, P + floor(驻军火力总和 / D))`。有真实主弹丸时至少射出 1 发；没有主弹丸时减去一个不会射击的主槽。因此城镇中心、强化教堂和码头不会凭空多出主箭；炮塔的 `P=0` 不会被改成 1 后再加额外箭，第二炮需要比率达到 2。条顿炮塔容量和上限增加来自自动科技 353，不来自垛口。

旧链接保留参数语义，旧 `garrison=N` 迁移为村民 83 的 `enter` 记录。通用理论模型会反映以前未导出的副弹丸效果：固定文件科技 64 对城镇中心副弹丸 54 有穿刺 `+0.5`，高丽在化学满足前置后免费获得该科技。满射程科技下建筑面板穿刺为 9，副弹丸为 9.5，5 村民火力为 22.5，本模型给出 4 箭；旧建筑面板分母给出 5 箭。数据模型保留原始效果的小数，该属性在同版本客户端的实际取整仍未核对，因此这是理论口径差异，不宣称已证明游戏行为或修复客户端错误。对应结果显示副弹丸与面板不同的提示。

新链接使用 `gv=2&army=单位ID:数量:e|c|d,...`，共用文明、时代、科技参数。重复键、混合旧参数、未知通道和损坏记录结构拒绝解析；结构正确的数量原文（包括编辑时删空）交给语义计算校验，允许继续修正。旧链接的损坏数量维持严格解析错误，界面须锁定到显式重置。
