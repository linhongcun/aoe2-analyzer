> 2026-11-08：日常 PR / main 的默认必跑已改为 [#749](ci-749.md) 的 static + build + Chromium 单分片窄冒烟。本文的四片、24 路由和日更 full 只保留给手动 `workflow_dispatch`（`full=true`）。不要把这些加回默认门禁。

## 固定原则

日常目标10分钟，每次PR/main/Release运行统一30分钟验证deadline；指标必须实测。起点为GitHub run.created_at，包含初始排队；同run的重试、阶段、聚合及deploy不得重置。到期、失败、取消、缺片或坏证明均不能签发成功证明或部署。另行记录提交到部署整链、Release等待、排队与runner分钟，不能只报告最慢job。诊断额外预算最多90秒，不能用于继续验证或变绿。

## 冻结的覆盖分层

- 每次：lint、typecheck、严格内容/公开来源/预编译校验器检查、严格分层；跨路由冷启动smoke、实际SHA构建、部署身份短核验。maintenance也保留短smoke，不沿用旧browser=none豁免。
- PR与main日常窄变更：使用实际审计的消费者闭包，完整保留所属功能正负路径与该功能自己的四宽/主题断言。首页的空大厅、未知模式/地图、失败恢复和文明保留，天梯缺快照与恢复，在受影响闭包包含该功能或高风险广覆盖时必跑；不要求每次文档改动执行无关首页长测。
- 公共计算、加载边界、全局CSS/tokens/路由、未知路径、策略自身改动：完整单测和广覆盖浏览器。真实数据、pins、依赖变化另执行真实再生成；数据阶段失败阻断，即使其它阶段通过。
- 夜间/手动完整：全部原断言、全部宽度/主题及历史全站hash/表格巡检；不删除spec或golden。高风险前台允许完整四片，取代旧“PR永不完整浏览器”的绝对限制；窄改动仍不展开无关全站巡检。
- 修正已发现的低估闭包：formatTime还影响builds/timeline，dupNames还影响search/duel，glossary还影响search；这些helper与linker、sharePage、simRoute先保守广覆盖，未证明完整消费者及测试闭包前不得仅按少数直接import收窄。全局Layout/Icon及共享editorial-shell样式同样保守广覆盖。
- feature目录CSS只有明确审计过的局部选择器可窄化；未知CSS、全局选择器与@import广覆盖。文明固定profile登记civHistory/civBackgrounds专项。
- 新旧影子比较至少覆盖：docs/version、CivDetail/localCSS、home/startGame、ladderQuery与未审计ladderStats、上述共享helper、simulator/realCost、globalCSS/tokens/routes/data-loader、data/pins/deps、来源schema安全子树与混合业务变化、未知/缺失diff/策略自身。对扩大和移到夜间的集合逐项说明。

## 工作流结构与接口

保留workflow名CI / Deploy、路径ci.yml、最终聚合job名test和Pages job名deploy，保持Release对实际test/deploy成功的依赖，不修改分支保护。

plan：确定真实Git树、精确测试文件/检查ID、风险级别、统一epoch/deadline和四片需求；输出不可变plan artifact与摘要。
static：核心静态检查。main专属unused/contrast/必要catalog audit作为独立static-main证明，不因PR核心证明复用而跳过。
unit：所需完整或精确领域单测；与static/data/build并行。
data：真实再生成，仅真实输入需要时执行；输出不一致必失败。
build：只构建一次，生成同一不可变site snapshot（实际SHA/tree/version/run/attempt/build-job、文件摘要、计划摘要及预期gate引用）。
browser：四个独立runner消费同一snapshot和确定性分片manifest，不各自重建；逐片独立报告/trace/截图。
test：always聚合，严格核对所有必需阶段、数据成功、四片集合和构建身份，再签发v2证明、上传同一快照为Pages/deployed-site。
deploy：依赖test，在自身排队后、发布轮询期间及完成后均检查同一deadline；到期中止并尝试取消远端发布，不签发成功结果。main始终真实重建其SHA，每个事件包括maintenance的build证明都必须含不可复用的fresh-build-smoke检查。
Release：继续下载准确main已部署产物，不再构建；校验v2 gate关联。自身run有独立30分钟epoch，整链另外汇总，不将前序等待隐藏。

新模块职责：

- ci-budget.mjs：GitHub-owned epoch、remaining、限时子进程/下载、到期拒绝、诊断预算、运行计时。
- ci-stage-evidence.mjs：v2阶段收据、精确集合/工具链/策略指纹、按tree+phase发现、原始执行证明验证、严格聚合。
- ci-shards.mjs与ci-browser-reporter.mjs：完整case枚举、确定性加权四片、所选与实际case集合校验、结果与timing报告。
- ci-stage.mjs：按plan执行static/static-main/unit/data/build/browser与aggregate，所有长操作共享budget。
- ci-scope.mjs/ci-run.mjs：保留安全文件解析、软链接拒绝和无匹配失败，不把空列表误称全量。

## v2证明与不可变构建

v1全部拒绝，首轮重新验证。每份阶段收据包含repository/id、run_id、run_attempt、实际数字job_id、stage_id、tested_commit/tree、event/base/head、policy/toolchain指纹、明确检查/测试文件/caseID及集合摘要、执行或直接复用来源、source_build身份、epoch/deadline/finished_at。

artifact名称含tree+phase，仅作为发现线索；核对GitHub-owned仓库、run/attempt/job、成功状态、head/tree/PR合并父关系、创建窗口、有效期、大小与digest。GITHUB_JOB符号名称不能冒充数字job ID。复用只指向原始实际执行证明，不允许任意继承链、子集冒充全量或v1升级。缺失、坏摘要、取消、过期、下载失败、指纹或集合不符均实际执行所缺阶段。

PR浏览器证明绑定自身受测构建及原始build成功证明；main来源树相同可复用源码覆盖，但必须构建main真实页脚SHA并做新构建smoke。所有当前实际执行的分片必须匹配当前同一snapshot，复用的PR分片证明允许绑定它原始且已验证的snapshot，不能任意替换，也不要求它与main新页脚的字节摘要相同。main专属静态检查必须独立补跑。构建snapshot在浏览器前冻结，浏览器后不往dist写收据；证明放独立artifact，通过不可变gate引用与manifest摘要关联，保留现有文件表/特殊文件名/symlink验证边界。

## 四片与静态巡检等价性

不使用按文件/测试数平均的原生shard作为性能保证，不全局fully-parallel。通过Playwright公开test-list选择精确cases，普通default/serial组保持原子；338的长循环组作为明确独立单元，加权LPT分配给四片。权重来自现有历史/本次测量，初次没有数据时明确标注保守权重，随后以实测更新。检查真实runner启动与排队，未知账户额度不能猜测为已确认。

manifest冻结project/file/titlePath/caseID/expectedStatus及snapshot身份。每片再次枚举并验证选择完全一致，聚合实际执行caseID的并集=原集合、交集为空；失败/取消/缺片/重复/漏测/非预期跳过/错构建均阻断。只批准既有screenshots的12个“未设置SHOT_DIR”运行时跳过，以及timeline的1个声明式fixme，精确冻结caseID/理由/条件；不能盲信执行后变成skipped的expectedStatus。CI禁止record变量，因此record相关skip不合法。完整计划固定四片，窄计划使用min(4,原子执行单元数)，不通过pass-with-no-tests伪造空片成功。

单测的公开Vitest list会省略已禁用的runIf/skipIf。冻结清单因此另外登记且只登记现有buildSim的1条todo、bonusUsage317的1条手工重录入口、v0300-289的1条递归计时入口，按精确文件和完整名称匹配且每条至多出现一次；实际报告仍必须包含这些ID且为skipped。同一文件的同名参数化用例用声明顺序中的出现序号区分，保留全部次数，不能去重。其它跳过和test.fail式预期失败一律拒绝。CI禁止开启上述重录/递归计时变量。新构建烟测使用公开test-list精确选择24条冷路由和1条实际HEAD/版本身份检查，逐ID核对实际执行。

`CI_DISABLE_REUSE=true`只禁用阶段复用，不改变当前必要范围；main专属静态检查和新构建本来就不可复用。规划时发现坏证据会实际执行缺失阶段；规划后才失效的证据在聚合时重新读取GitHub元数据与原始ZIP并失败关闭，不把已跳过的job冒称补跑。

完成计时观察在Release结束后执行，避免观察job与Release既有全部check门禁竞争。Release准备阶段保存经独立API核验的准确源CI run/attempt；观察器据此读取main与原始PR阶段来源，并单列人工作审阅/合入等待。未知的服务端收件时间保持未知，不能用Git作者/提交时间冒充。手工CI validation probe对真实来源先做正对照，再在已核验下载边界仅注入receipt.version=1，要求明确拒绝原因并实际执行窄功能单测/浏览器集合；实验只产出诊断报告，不生成可复用生产证据。

## 验收与实验顺序

1. 先提交独立复核的失败验收/影子计划；基线必须实际失败，保留旧断言。
2. 预算到期（包括运行中、聚合排队、deploy排队）、假job/attempt、旧v1、坏来源、缺片/重复/漏case、data失败、错snapshot等注入均不能绿灯或部署。
3. 固定候选构建上比较新旧(route,width,assertion-family)集合与故障检出；hash与表格同时坏时两者均报告，六份fixture不变。
4. 实跑窄功能、高扇出完整、同树main可信复用、坏证明回退四种场景，记录覆盖集合、关键路径、全部排队、最慢片、runner分钟、失败反馈延迟与PR→main→deploy→Release整链。验证实验不得冒充生产成功证据；若需临时实验PR，明确仅验证、最终关闭且不作为第二个产品实现PR。
5. 普通争取10分钟；广覆盖必须在统一30分钟内实际通过，否则保持问题未完成并继续优化。夜间同样实测，不能仅挪走慢测试或配置timeout便验收。
6. 回退可关闭阶段复用或恢复旧选择/执行模式，但保留断言与deadline，超预算明确阻断。

执行环境在审计期间断开；源码仍可由GitHub应用准备，真实执行拟由GitHub Actions完成。不会把未执行检查写为通过；环境恢复后也沿同一固定源码和计划验证。
