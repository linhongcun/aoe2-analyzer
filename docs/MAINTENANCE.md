# 维护与协作规范 / MAINTENANCE

本文件适用于 Cursor、Codex、Claude Code、Devin 及其他编码代理。人类与角色代理仍以 [CONTRIBUTING.md](../CONTRIBUTING.md) 为准；本文件与 CONTRIBUTING / [AGENTS.md](../AGENTS.md) 冲突时，以 CONTRIBUTING 为准，并在 issue 里指出。

入口：先读 AGENTS.md → 本节授权核验 → 当前原始 Issue。

Issue 阶段、同一正文、角色认领与交接统一按 [CONTRIBUTING「Issue 生命周期」](../CONTRIBUTING.md#issue-lifecycle) 执行；本文件只补充执行门禁，不另建阶段流程。

已记录的维护者持续合并、审阅、发布与关闭授权以 CONTRIBUTING 为准。授权仅作用于原 Issue 明确范围；本文件不授予 backlog 范围、不解除 Hold，也不复制一次性批次状态。

## 当前工作授权与 Issue 状态

开始、继续或选择工作前，读取原始 Issue 的最新正文和授权，核对当前状态、阶段及待确认/阻塞/候选/已部署标签、产品范围、验收标准、非目标、认领/负责人、关联 PR、Hold 和外部依赖。以 Issue 最新记录为准；标签、历史授权或空闲 backlog 均不单独授予实现权限。

进入软件开发前，必须在同一 Issue 中有明确且仍适用的实现授权、可核对的范围/非目标/验收标准，并完成 Issue 生命周期要求。一个实现写者对应一个 Issue/PR；同时在审 PR 不超过 2 个。不得重复实现已有开放 PR 或他人有效认领的工作。关闭的 Issue 不得重开或重复实施，除非维护者在原 Issue 记录新的明确授权。Hold 只能按维护者在原 Issue 记录的明确授权解除。

本文件不列当前 Issue、批次、Hold 或 backlog 清单；历史授权和交付证据以原 Issue、PR、Git 与 Release 记录为准。

## 1. 产品主题（是什么 / 不是什么）

**是什么**：帝国时代 II 决定版（AoE2 DE）的**中文资料站 + 计算工具**——文明/单位/科技/建筑百科、科技树与加成，以及对比、对局助手、模拟器、单位 PK、开局、市场预算等可分享的计算页。线上：https://linhongcun.github.io/aoe2-analyzer/。界面文字全部简体中文。数据版本以页脚与 `scripts/data_sources.json` 为准。

**不是什么**：

- **不编造游戏数值。** 数字只从生成数据与固定 `.dat` 派生结果读；记忆、旧帖、猜测一律不算。issue / 设计稿 / 测试与数据冲突时，以数据为准并在 issue 说明。
- **不做无关大功能。** 不做实时读盘、账号系统、自动推荐最优策略、改游戏平衡、爬站批量抓内容、自建天梯后端等偏离「资料 + 计算」主题的扩展，除非维护者在 issue 里明确授权并写入范围。
- **不做未授权的批量集成。** 一个 issue 一个实现 PR，按批准顺序串行；不得伪造他人审阅结论。是否合并、发布按维护者已记录的授权执行，不能把持续发布授权解释成自动领取所有 issue。

## 2. 工作节奏

1. 每个角色/执行者一次只认领 1 个 Issue；继续自己的有效认领后再选新项。不同角色依阶段更新同一 Issue；软件实现仍由一个执行者负责一个 Issue/PR。认领和交接按 [Issue 生命周期](../CONTRIBUTING.md#issue-lifecycle) 记录。
2. **同时在审的 PR ≤ 2**（含别人的）。审阅位满时只准备草稿，不新开 PR。
3. 当前 PR **合完再拿下一个**；不要并行囤积分支等合。
4. 选择新 issue 或准备新开 PR 前先查关联 PR；新候选已有 open PR 时跳过，避免重复实现。自己仍有效认领的事项已有 open PR 时，继续同一个 PR 的 CI、复核、修复与交付，不重新认领或另开 PR。
5. 普通已授权更新默认一个 issue、一个 PR 直接对最新 main；仅需要多项冻结集成时使用 `release/vX.Y.Z` 并更新到其最新提交。
6. 开发实现时的兼容取舍见 [AGENTS「开发执行」](../AGENTS.md#dev-exec-2026-11-10)。每 PR 测试门禁以 [TESTING](TESTING.md) 文首为准。

## 3. 门禁（对齐 CONTRIBUTING）

复核、测试、合并、部署与关闭以 [CONTRIBUTING](../CONTRIBUTING.md)、[TESTING](TESTING.md) 和 [RELEASING](RELEASING.md) 为准：

- 实现者之外的独立代理复核范围、验收、代码/数据来源与相关测试；PR 记录实际验证的 SHA、复核结论和未解决事项。不得伪造他人结论或把未解决问题写成通过。
- 按 TESTING 对本次改动选择必要冒烟和直接相关测试；CI 计划、证据复用、手动 full 与部署条件不在此重复。纯文档/样式且不动逻辑和测试时，适用 CONTRIBUTING 的 CI 绿轻量规则。
- 网站实现 PR 使用 `Relates #N`，待真实部署、线上核对和正式 Release 后关闭；`Fixes #N` 仅用于合并即完成的事项。已合并不等于已部署或已正式发布。
- 不通过删除断言、跳过必要测试、伪造复核或扩大旧授权来消除阻塞；产品范围与 Hold 由维护者在原 Issue 决定。

## 4. Hold（勿开）

开工前核验原 Issue 的当前 Hold、待确认、阻塞、认领和依赖状态。不得自行打开、解除、绕过或清除 Hold；只有维护者在原 Issue 明确记录的授权可解除具体 Hold。此文不维护当前 Hold 清单，也不因历史批次或标签改变 Hold 状态。

## 5. 跳过（不要开工）

遇到下列任一情况，**跳过**该 issue：

- 标签 **`待确认`** 或 **`阻塞`**
- 新选择的 issue **已有 open PR**，应跳过新认领/重复实现；自己仍有效认领的已有 PR 应继续同一个 PR，不另开 PR
- 属于当前 Hold、待确认、阻塞或未获明确范围/实现授权的事项
- 已关闭的 Issue 不重开、不重复实施，除非维护者在原 Issue 记录新的明确授权
- 正文缺少可核对的 **「验收标准」**，或缺少 **「不要做」/「不在范围」**。只有空的「-」、没有可核对的功能结果，都算没写完。执行者可在已授权范围内先补齐规格并交独立代理复核，不得自行发明产品范围
- 标题形如「待村长确认」的版本范围

### 开工就绪检查

开写前正文应能逐项勾上。缺任一项，执行者跳过，或只在已授权范围内补规格，不直接实现：

- [ ] **玩家场景**：谁在什么情况下要用
- [ ] **验收标准**：能说明这次功能怎样算正常，不是空的「-」
- [ ] **不在范围 / 不要做**：写明这次明确不做的事，不是空的「-」
- [ ] **涉及页面 / 路由**（如 `#/ladder`）和数据来源；没核对的写「未核实」
- [ ] 验收按本次任务明确相关桌面/窄屏状态；不设固定视口矩阵，测试范围见 [TESTING](TESTING.md)
- [ ] 改界面：交接到软件开发前，体验设计交付的完成态设计图已直接嵌入同一 Issue 正文，能查看并覆盖主要界面和重要状态；文字、规格、线框、本地文件或 ZIP 不能替代。只有纯 docs/data 且无 UI 时可由产品记录 UX 不适用及理由

写 issue 和实现时都守这些产品口径：不编造游戏数值；不接 live 天梯；天梯等静态快照标明非当前平衡和统计截止。缺来源就标「未核实」。

## 6. 设计硬规则（摘要）

通用原则见 [体验设计指南](design/DESIGN-SYSTEM.md)；具体需求、设计图与交接记录在原 Issue 正文，不以本地短稿或勘误替代。

- **图标**：只用 Lucide，经 `src/shared/ui/Icon.tsx` 的 `ICONS` 登记后 `<Icon name="..." />`；禁止 emoji / Unicode 符号当图标（ESLint 会拦）；游戏美术图标除外。
- **颜色**：只用 `src/shared/styles/tokens.css` 设计令牌；`npm run lint:colors`。
- **无障碍**：文字对比度 WCAG AA；可点区域 ≥ **44×44**；文字不小于 12px。
- **数字不换行**：数值与「数字+单位」用 **`.num`**（等宽数字）与/或 **`.nw`**（`white-space: nowrap`）包住，360 宽也不能折行。
- **视口**：按本次任务检查相关窄屏和桌面状态，无横向滚动或页面错误；不要求固定宽度矩阵。
- **中文 UI**：文案与相邻页面一致；新增页面先改 `pageRegistry`，分组见 [ARCHITECTURE](ARCHITECTURE.md)「路由、导航与元数据」。

带界面的事项按 [体验设计接手指南](../role/experience-design.md)交接。

UI 的当前规格和完成态设计图写在同一 Issue 正文“体验设计”节；体验设计交付并交回产品确认前，实际 UX 工作必须嵌入可直接查看、覆盖主要界面和重要状态的设计图。只有纯 docs/data 且无 UI 时可记录 UX 不适用。不得仅为阶段变化新建 Issue 或功能规格文档。缺少可执行规格或设计图时不得标记设计交付完成或转软件开发。具体交接见 [Issue 生命周期](../CONTRIBUTING.md#issue-lifecycle)。

当前体验设计原则、图标、令牌与角色分工以 [体验设计系统](design/DESIGN-SYSTEM.md)、[体验设计接手指南](../role/experience-design.md) 和 CONTRIBUTING 为准；不把未定义的历史方向标签作为现行规则。

## 7. 测试规则

每次改动的适用测试、默认 CI、手动 full 和验证报告要求，以 [TESTING](TESTING.md) 为准；不把历史检查矩阵或固定视口要求当作每 PR 门禁。数据正确性按本次改动针对性核验。发布、部署、线上与正式 Release 的流程见 [RELEASING](RELEASING.md)；本文件不复制工作流、证据复用或预算细节。

## 8. 选 issue 流程（checklist）

开工前逐项勾选：

- [ ] 已读 AGENTS.md、本文件的[授权核验](#issue-authorization)及 CONTRIBUTING 门禁段，并查验原 Issue 最新状态、授权、认领、关联 PR 与 Hold
- [ ] 已核对当前具体授权；issue 不在仍有效的 Hold／待确认／阻塞中；新选择的 issue 无已有 open PR（自己仍有效认领的 PR 继续原 PR）；不重开或重复实施已关闭的 Issue，除非原 Issue 有新的明确授权；已交付的 OPEN issue 不重复实现，核实交付后按持续关闭授权关闭
- [ ] 正文当前阶段与唯一 `阶段:*` 标签一致；按自身角色认领，读取最新正文、认领和关联 PR；不得接管他人有效认领
- [ ] 进入软件开发前，同一正文已有针对本事项的明确实现授权；阶段标签、设计通过和持续发布授权都不代替该证据
- [ ] 交接至软件开发前，正文已有具体、非空、可测的 **验收标准** 与写明事项的 **不要做 / 不在范围**；空白、「-」或「待评审」都不算就绪。需要补齐时先留在前序阶段，按授权补全并复核后再交接；主题仍是「中文资料站 + 计算工具」
- [ ] 当前在审 PR 数 **&lt; 2**
- [ ] 从**当前已授权范围和自身单一阶段**挑选尚未完成的事项，核对实际代码、正文、认领及已合并/开放 PR；继续自己的有效认领，不接管他人认领；不要继续使用已完成 issue 的旧示例选单，也不要把“超出上一轮小修”解释成“项目无法推进”
- [ ] 新页面/大功能先在原 Issue 获得明确范围和实现授权，完成可测规格与设计交接并经实现者之外的独立代理复核后再实现；不要自行扩范围
- [ ] 分支名与 PR 标题符合 Conventional Commits：`类型(#issue): 描述`
- [ ] 测试按 [TESTING](TESTING.md) 文首：功能是否正常、必要冒烟和直接相关测试。`Relates` / `Fixes` 仍按该文编码代理交接；此处不另写门禁

## 9. 发版

持续合并与发布授权以 [CONTRIBUTING](../CONTRIBUTING.md) 为准；当前准备、CI/Deploy、Pages 核验、自动 Release 与恢复流程见 [RELEASING](RELEASING.md)。已合并不等于已部署或正式发布。

## 10. 路由、导航与元数据

页面登记的唯一来源是 `src/shared/nav/pageRegistry.ts`。路由、导航、首页和静态元信息都从它派生，不要手改 `routes.tsx` 或另一份名单。字段、`import()` 所在文件和测试见 [docs/ARCHITECTURE.md](ARCHITECTURE.md)「路由、导航与元数据」与 [AGENTS.md](../AGENTS.md)。本文不重复 API。

## 11. 交给人类的事

- Hold 变更、未获授权的范围/产品决定；必须由维护者明确授权，不伪造他人结论
- 合并/发布按已记录授权推进，不反复把同一发布决定交回维护者；没有相应授权的仓库权限变更仍交维护者
- 有意替换旧布局、入口、链接或重复功能时，按 [TESTING](TESTING.md) 更新用例，不必单独请示。计算或数据结果仍交维护者决定
- 产品范围与「待确认」事项由维护者明确决定
