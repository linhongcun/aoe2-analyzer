# #288 组件职责拆分规格

本项整理开局时间线与单位 PK 的文件职责，不改变产品状态、中文文案、数据来源、计算规则、URL 参数、HTML 标签或 CSS。继续使用现有设计令牌、字号及间距。

## 开局时间线

- `useTimelineSettings` 负责 URL 参数解析与 replace 更新、提示的 sessionStorage 状态、手机设置抽屉、打开/关闭焦点及 Escape、当前开局胶囊滚入可视范围。
- `TimelineSettings` 保留电脑内联和手机抽屉的原有设置控件，含通用文明、未支持文明提示、走路距离近中远及滑条、自动造房开关和匈奴无需房子的置灰状态。
- `TimelineChart` 原样承载时间线轴、资源与单位条、时代误差带、卡点、图例及估算说明；`TimelineSteps` 原样承载键盘导航、村民生产分组及步骤详情。
- `domain/buildTimelineLayout` 接收已有模拟结果，处理整分钟轴长、坐标裁剪、刻度间隔、主卡点引用及浅色条合并，不依赖 React 或功能模块。
- 分享链接、分享卡/手动复制回退、跟练/打印入口、步骤展开与跳步保持原行为。受保护验收用例的期望不修改。

## 验证

布局先失败测试见 `tests/unit/buildTimelineLayout288.test.ts`，覆盖边界裁剪、空轴、10/30 分钟刻度阈值、卡点主次选择、相接合并以及输入不变性。保留现有开局、匈奴、分享与跟练回归，检查 360 / 375 / 390 / 1280 浅色和深色下无横向滚动、页面错误，设置与步骤操作保持可用。

## 单位 PK

`Duel` 保留 URL 解码、规范化与 replace 更新、加载态及模式协调；`DuelSelection` 负责双方的单位/文明/科技选择、折扣与不可用状态；`DuelResults` 负责单挑、群战及资源交换结果；`DuelTimeline` 负责攻击点和存活数量 SVG。双方类型与现有解析搬到 `logic/duelSide`，游戏公式仍调用原 domain 模块。原 `h1/h3/h4` 全部保持，不触碰 #364 标题整树调整。

| 状态                         | 必须保持的行为                                                             |
| ---------------------------- | -------------------------------------------------------------------------- |
| 数据加载中                   | 原页面标题与 Loading，占位完成后才可读取结果                               |
| 单挑                         | 双方选择、伤害表、回放、攻击点、伤害拆解与升级对比保持一致                 |
| N vs M                       | 改数量更新 URL，结果、交换比、回放和 SVG 同步刷新                          |
| 等资源 / 等采集时间          | 切换比法和预算沿用现有 URL 参数清理规则，折后数量和采集时间披露保持一致    |
| 单位不可用                   | 保留所选文明与 URL，不显示对战结果；显式点击替代按钮后才更新单位并恢复结果 |
| 科技详情展开                 | 原 SimPanel 控件及标题标签保持一致，改变科技会重新计算结果                 |
| 开局默认 / 匈奴 / 未支持文明 | 默认计算、无需房子的置灰、通用计算与会话提示键保持一致                     |
| 手机设置打开 / 关闭          | 首控件焦点、Escape 关闭回到设置按钮，修改参数只 replace 当前历史记录       |
| 步骤展开 / 跳步 / 估算说明   | URL 选中步骤、左右键与 Escape、卡点定位和假设说明保持一致                  |
| 分享卡 / 手动复制 / 跟练打印 | 原有入口、可用性、临时 URL 清理与关闭回焦不变                              |

在 360 / 375 / 390 / 1280、浅色和深色逐页核对布局与关键交互；新四宽用例存截图，DOM 与最新 main 的同状态另做本地直接对照。颜色、字体和间距沿用所有现有 CSS 令牌与类名，不引入新视觉值。

## 工程规模护栏

TS/TSX 按物理行计数，超过 500 行 warning；除固定记录的现有超长路径外，超过 600 行 error。新文件自动接受两级限制，基线不会动态增加。CSS 超过 800 行 warning，语法错误仍阻断。`ts-prune` 作为只报告的未使用导出检查，发现本身不阻断，工具实际执行失败仍报错；删除已确认无引用的 `CampaignSort`。

预审：root 独立核对以上拆分范围与布局先失败测试后同意实现，要求保留两级门禁、URL/sessionStorage/焦点与 effect 清理、原 DOM 标题标签及四宽状态。此记录是实现前范围审阅，不代替最终提交复核和验证结果。
