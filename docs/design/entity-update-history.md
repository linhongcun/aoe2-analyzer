# 文明、单位与科技更新历史

维护者于 2026-10-25 在聊天中批准按“历史档案、三类详情页、分批补齐”实施。直接扩展既有版本补丁页；本规格是首批交付范围。

## 范围与证据

- 首批录入 DE 正式版 66692（2022-08-29）、81058（2023-04-11）、125283（2024-10-15）的文明平衡栏目，并保留现有 185872 数据。收录范围逐版说明，非连续完整历史；不把无记录解释为从未改动。
- 三个历史补丁只从本轮实际打开的官方公告逐条整理，保存英文原文摘录、中文摘要、前后值、链接、核对状态及核对日期。旧值、新值来自当时公告，不用当前游戏数据反向证明旧补丁。
- 正式发行日与公告日分开；125283 标题虽为 Preview，但 10 月 14 日公告明确次日上线，10 月 15 日正式玩家报告亦确认 build。剥离同页后来追加的 71094、127161 等热修。
- 历史源文件使用 releaseDate 保存官方公告当地标注的发行日；sourcePublishedAt 保存完整来源发布时间戳，publishedAt 为该时间戳换算的北京时间日期。界面同时明确标注两种事实，不能将公告公开日充当游戏发行时刻。既有 date 字段遵守 #335 的来源日期规则，加载器内部以 releaseDate ?? date 规范化时间线记录日期；不改变 #335 任何断言，只按其既定登记流程增加真实来源时间戳。
- 每条支持新增、加强、削弱、混合调整、机制变更和修复；无法单向判定的组合调整归“调整”。当前站点的数据修正不冒充历史平衡变更。
- 既有 kind=fix 保留“本站数据修正”原义；官方游戏修复使用 kind=adjust / changeType=fix，并显示“游戏修复”，不能计为数值加强/削弱。
- 不采集天梯胜率、不做整体强弱排名、不改模拟器与当前游戏数值；原版、征服者、HD 与测试版留待后续批次。

## 数据契约

- 扩展 PatchEntry 的可选字段：originalText、verification、changeType、relatedTargets、affectedCivIds、scopeNote。旧版 JSON 保持兼容。
- relatedTargets 使用 targetType / targetId / targetNameZh，保存历史明确的关系及条件。文明历史只采用当时明确的 civIds / affectedCivIds，不以当前科技树推断早期可用性。
- 同一事件只保存一次；时间线匹配主目标显示“直接改动”，匹配 relatedTargets 显示“关联影响”，同条命中主目标与关联目标时去重且优先直接。
- 普通与精锐各按明确身份匹配，单位升级费用与生产费用区分。科技被替换或数字 ID 被复用时使用独立历史键，避免旧科技错误并入当前科技。
- 已删除/当前目录缺失的科技有独立历史详情，支持直接链接、返回版本以及查询。只展示历史描述，不伪造当前属性、图标或可用文明。
- 独立历史输入与生成器可重现历史 JSON；校验版本、日期、链接、ID、引用、非空证据、唯一记录及生成结果。历史输入不是当前生成数据的手工覆盖。
- 保存平衡栏目 sourceBullet 清单到记录/明确排除原因的映射并生成覆盖报告，只有全部映射核对后才声明栏目完整。185872 无逐条原文/verification 的记录显示“既有来源记录，尚未完成逐条原文核对”，不默认已核实；缺少前后值时只显示已知内容。

## 界面与状态

### 详情页

- 文明、单位、科技既有 DetailPage 末尾增加“更新历史”页签，URL 为 ?tab=history。复用既有键盘左右/Home/End 行为，既有页签与默认内容不变。
- 历史组件按需加载。加载时显示“正在加载更新历史”；失败显示说明与“重试”。切换实体不得短暂显示上一对象的记录。
- 顶部说明首批版本、分批收录、历史数值不代表当前数值，以及数值改动不等于整体对局强弱。
- 筛选：关键词、改动类型、直接/关联、开始/结束日期、时间顺序；写入 hist 前缀 URL 参数，保留 tab/civ/elite 等现有参数，刷新/分享可重现。默认全部、由新到旧。日期端点包含当天，起日大于止日显示“开始日期不能晚于结束日期”。
- 按版本分组显示日期、DE/正式版、版本链接；记录显示目标名称、直接/关联标签、类型、中文摘要、前后值、适用文明/条件、来源及核实状态。英文原文放在可展开 details 内。
- 无档案显示“尚未收录该对象的更新历史”；筛选无结果显示“没有符合筛选条件的记录”及清除按钮；两者不混淆。清除只清历史参数。
- 历史缺失科技显示“历史档案，当前数据目录未收录”，有中文/英文历史名及时间线，不展示当前科技费用等。

### 版本补丁页

- 版本列表同时列出四个版本，按正式日期倒序，显示各版覆盖范围。
- /patches/:id 使用对应版记录、日期、来源和说明，不再把 185872 的其他内容、数据验证文字套给历史版。
- 保留既有按文明/类型/关键词筛选与科技树得失汇总；历史版汇总明确前后状态依据当时官方记录。
- 从记录可进入对象的历史页签；历史科技链接不能落到普通科技列表。未收录版本保留“还没收录”的明确状态。

## 可验收视觉规格

- 使用现有 DetailPage、设计令牌和 Lucide 图标，正文 15px、辅助文字 13px（最低 12px）、控件/来源链接最小 44×44。
- 内容卡片 --color-surface，边框 --color-border，正文 --color-text，说明 --color-muted；加强 --color-good，削弱 --color-bad，并始终保留文字标签；其他类型中性。圆角 --radius-md，间距 --space-3/4/6。
- 1280 宽筛选采用可折行网格，时间线单列；360/375/390 宽筛选单列，日期/前后值上下堆叠，长名称/英文原文可断行。数字及数字+单位用 .num/.nw，不将整段资源列表设 nowrap 导致溢出。
- 四宽分别检查浅/深主题，无页面横向滚动、console error/pageerror、无不可见来源链接；折叠原文、空/加载/错误状态可操作，键盘能进入所有控件。

## 失败用例与验收

1. 弩手 24 的历史至少包含 66692 成本上调与 125283 黄金部分回调，按日期排序；两条均说明是升级成本，不是生产成本。
2. 古拉姆普通/精锐 1747/1749 分别显示正确 HP；无关联说明时不混入另一形态的专属数值。
3. 勃艮第文明可查 66692 的经济科技折扣及其专属单位变化；不凭“全局”标签将未核实的适用关系投放到所有文明。
4. 软甲 875 的新增记录及其对民兵系的条件影响可在相应详情看到；关系显式保存，不从当前科技树猜测。
5. 已不在当前目录中的补给与被替换旧科技能打开历史详情，有证据且不冒充当前科技。
6. 起止日期包含边界；种类/关系/关键词取交集；无结果可清除，URL 刷新不丢筛选；旧页签 query 保持。
7. 版本页能分别打开四版，66692 不夹入 71094，125283 不夹入 127161；未知版不错误显示最新版。
8. 历史生成器校验唯一键/来源/引用/覆盖声明，重复生成一致；不依赖当前新值校验旧补丁。
