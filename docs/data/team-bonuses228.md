## 目标关系与边界

- 单位属性命令读取 `A` 单位 ID 或 `B` 原始对象 Class；不把 `units.json.cls` 的护甲类当对象 Class。
- 建筑时代形态仅按固定时代 effects101/102/103 的原始升级命令归并到站内建筑，例如87/10/14是同一靶场目录。未映射对象保留 ID，不能靠名字猜归属。
- `targetUnits`、`targetBuildings` 是直接属性/启用/升级目标；`productionUnits` 只对生产建筑的工作速率属性13导出，使用全站单位目录和原始 `TrainAt`，不限定于来源文明。它是间接生产关联，不表示单位自身属性改变。
- 启用单位或升级科技的目标，仅表示存在来源关系；不表示任何文明、任何时代已拥有该单位。`chain` 保留前置科技、所需数量和研究地点。
- 每条已展开科技链另自动生成具体条件备注，写明原始时代、启用/研究/修改时间模式、研究地点、前置ID与数量。柏柏尔精锐升级599明确“帝王时代；仅启用，不代表已经研究；仍需在靶场完成研究”，避免只看标枪骑兵原始常驻说明而忽略精锐门槛。当前时代只约束此页团队UT研究记录；目标目录是跨时代来源审计。
- 资源、引擎函数、科技费用/研究时间修改、解锁条件及未映射目标产生 `unknownTargets`。`targetCoverage=complete` 仅指已枚举站内的直接静态对象关联；`partial/unknown` 不应被单位筛选静默隐藏，也不能宣传为完整游戏机制覆盖。

生成文件只提供来源与关联，中文说明及实体详情链接复用现有文明/科技资料。它不会向旧 PK、建筑、经济模拟器或旧 URL 注入队友效果。

`effectTypes` 是供界面显示的命令类别，独立于筛选字段 `kinds`，不计算倍率。完整枚举为 `attack`、`attack-speed`、`health`、`armor`、`range`、`vision`、`production`、`cost`、`attributes`、`resource`、`unlock`、`research`、`other`。属性0/1/8/9/12/20分别对应生命、视野、护甲、攻击、最大/最小射程；属性13仅在建筑目标时标生产，属性101按生产/建造时间分类，并同时加入 `kinds.production`，避免训练时间与房屋施工来源被生产筛选漏掉；成本为100/103/104/105/106。属性10兼用于信仰恢复间隔，只有已知原始对象同时有攻击项和正Reload才标攻击速度，否则保留泛属性。属性23是搜索半径，不冒充视野。资源命令1/6、解锁/升级2/3、科技修改8及101–103分别单列；未知字段只标泛属性或其他。
