# 对局助手的文明上下文与可用性（#469）

冻结基线：`4794b0cba28eb2b728cf97c6ad9931ff3ab85b6d`，DE Update 188329，计划版本 `0.61.0`。沿用已获独立 GO 的 `/tmp/issue469-preflight.txt` 与 `/tmp/batch-protected-readiness.txt`。只纠正现有对局建议、演练和开局入口的文明资格，不增加教练、最优配兵、胜率或资源排队模型。

## 固定行为

- 使用 Matchup 原有两个 CivPicker 的当前本方/对手文明；早期进攻区域仍只有原来的一个打法下拉框。`rush` 参数及其默认、切换、回退行为不变；不新增源页文明分享协议。
- 保留四组原单位与数量：步弓手 4 对民兵 74，人数 2/3；长矛兵 93 对斥候骑兵 448，人数 2/3；掷矛手 7 对步弓手 4，人数 4/4；村民 83 对村民 83，人数 6/5。不替换单位、人数、文明或压力选择。
- 所有当前演练明确为封建时代（2），无团队加成、无主动科技；塔爆仅双方各研究可用的织布机 22。保留 PK 已建模的常驻文明加成与既有模拟限制。两侧分别用实际文明经 `fmtSide` 生成自足 URL，目的页不依赖旧 sticky 状态。
- 双方单位都须有实际单位目录成员资格和可用的 `u` 型科技树格。同号 `t` 格不能代替单位。时代取文明已有 `EARLY_UNIT_AGES` 例外；无例外时同时满足目录时代与树格时代（行 0/1 黑暗、2/3 封建、4/5 城堡、6/7 帝王）。亚美尼亚 93 的真实黑暗时代树格允许时代 1；普通 93 的封建树格阻止其目录时代 1 误放行。亚美尼亚 75 等沿用既有提前解锁例外，不改共享 domain。
- 科技须匹配 `t` 型可用树格、目录文明与时代；塔爆任一方 22 不可用时隐藏演练，并解释原因，不保留“均已织布”的可点击标签。任一方单位不可用时保留所选打法，解释本方/对手的实际文明、单位与时代，不生成伪装为当前对局的 PK 链接。本方防守单位或所需科技未确认时不展示出兵数量建议。
- 开局入口独立核对原模板的全部显式 `train.unit` 与 `upgrade.unit`；后者是目标形态，不是科技或基础兵。每个形态须在该模板的目标时代对本方可用；否则隐藏该入口并解释具体不可用单位，不自动换模板。合法链接始终含原 `bo` 与本方 `civ`。`simSupport` 不充当单位资格，经济加成范围继续由开局页原提示说明。
- 示例：玛雅对不列颠的斥候压力可提供 93 对 448 的 PK，但不能提供会训练 448 的玛雅斥候开局；对手为玛雅时该压力的 448 不成立。印加的 `u74=0` 不被同号可用科技误放行。
- 原 `filterCounterUnits`、评分、门槛、`matchup` 数学及 #424 的通用单位/文明模拟链接保持。补充文案仅在 feature 内逐个单位分句核对真实树格；去掉不能造的骑兵、轻骑、骑射等分句，保留成立的原建议和中性墙/阵型说明，不根据评分推导资格。不将某个可用分支概括成另一个不可用分支；“城堡期蝎子”须实际 279 在时代 3 可用。反制区仍按原默认帝王时代说明。

## 加载、错误与界面

Matchup 使用唯一的 feature-local 捕获加载状态，通过 `Promise.all(loadCore, loadTrees)` 取得同一份 core/trees 后传给早期进攻区与反制展示。替换本页原 `useCore` 调用，避免另一条未捕获 Promise 链；共享 hooks、缓存和加载器不改。加载中保留双方选择器、打法选择和中性防守/来源说明，隐藏未验证的 PK/开局及反制结果，显示“正在核对双方文明的单位和科技…”。真实分包失败时显示 alert“对局资料加载失败，暂时无法核对演练和开局。请刷新页面重试。”，不再显示加载中，不提供不会清除拒绝缓存的伪重试。

沿用 `.rush-defense` 与现有 token：正文页面字体 15px、说明 `--fs-sm` 13px，文字 `--color-text`/`--color-muted`，链接 `--color-link`，边框 `--color-border`、圆角 `--radius-md`，间距原 1rem。原 CivPicker 保持键盘管理，打法选择与链接至少 44×44px，焦点可见。人数和“数字+人口/兵种”用 `.num/.nw` 或现有 nowrap 包裹，完整可访问名称不变。360/375/390/1280 × 明暗主题均核对正常、不可用、空补充、加载和错误，无横向溢出或非预期页面错误。
